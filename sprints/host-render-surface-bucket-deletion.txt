# Host Render Surface Bucket Deletion

Purpose:

- Delete stale host bucket ownership while including the render ABI and per-surface texture seams in the cleanup scope.
- Supersede `sprints/host-loop-bucket-deletion.txt`, which is stale because it scoped render/present orchestration too narrowly and skipped the render ABI/surface-type cleanup now required by the user.
- Keep product code unchanged until the user accepts or rejects this sprint contract.

Problem statement:

- `howl-linux-host/src/buckets that must die/host_loop_bucket.zig` is not one owner. It mixes the main/window loop, typed host events, input admission, tab commands, active-tab title/focus sync, render-turn admission, terminal texture upload, layout-frame construction, present-reason selection, and present submission.
- `howl-linux-host/src/buckets that must die/bucket2.zig` still exposes the misleading public type `Surface` for a terminal runtime instance. It owns PTY/VT/render/input/cursor/scrollbar/selection/link state and render-turn sequencing, not a generic surface.
- Render ABI names are currently too broad at the host seam. `HowlRenderSurfaceFrame` is a render command frame, while `HowlRenderHostSurface` is a stale generic token that hides the fact that terminal, tab bar, and scroll bar surfaces are typed, loosely coupled, and independently driven.
- Terminal, tab bar, and scroll bar presentation are unique, loosely coupled surface types. They must not be collapsed into a generic `host surface` bucket, a generic `host_render` owner, or one shared host-surface ABI token.

Required source facts:

- `howl-linux-host/src/buckets that must die/host_loop_bucket.zig` owns `Processor`, nested `RenderSnapshot`, `RenderUpload`, `RenderFrame`, `PresentReason`, active-tab routing, `render`, `uploadPreparedPanes`, `submitPresent`, and `presentFrame`.
- `howl-linux-host/src/buckets that must die/bucket2.zig` exports `Surface` but that struct contains `term: HowlTerm`, PTY progress, surface-present trigger, render retained state, input thunks, cursor cadence, scrollbar state, selection, links, and PTY/VT lifecycle.
- `howl-linux-host/src/texture/frame.zig` owns the main-thread GL texture frame state and directly contains terminal presenter slots, tab bar cache/text prepare, terminal pane draw, scroll bar draw, and EGL swap.
- `howl-linux-host/src/texture/term.zig` owns a per-terminal `Presenter` slot with `HowlRenderHostSurface` plus render resource textures. This is a real terminal texture owner, not terminal state ownership.
- `howl-linux-host/src/texture/tab_bar.zig` draws tab bar background and writes bounded tab bar cells for the cell-surface ABI path.
- `howl-linux-host/src/texture/scroll_bar.zig` draws scrollbar rail and chip only. It has no render ABI dependency and should stay small.
- `howl-linux-host/src/render/surface_retained.zig` owns terminal retained render state and calls `howl_render_text_prepare` and `howl_render_text_submit`; its alias `HostSurface = c.HowlRenderHostSurface` obscures the texture-token seam.
- `howl-linux-host/src/render/surface_layout.zig` owns terminal render layout synchronization and point-to-cell queries through the render text ABI.
- `howl-render/include/howl_render.h` defines the ABI facts: `HowlRenderSurfaceFrame` is the prepared command/resource/damage frame; stale `HowlRenderHostSurface` is `{ host_surface_id, width, height }`; `HowlRenderTextPrepare` is VT text input; `HowlRenderCellSurfacePrepare` is bounded cell-text input for surfaces such as the tab bar.
- `howl-render/src/text/surface.zig` uses one `TextSurface` handle for VT text preparation and bounded cell-surface preparation, but these are distinct prepare inputs: `prepare` for `HowlRenderTextPrepare` and `prepareCellSurface` for `HowlRenderCellSurfacePrepare`.
- `howl-render/src/surface/emitter.zig` owns emission of `HowlRenderSurfaceFrame`; it does not own host GL textures.

Target owner model:

- `howl-linux-host/src/host_loop.zig`
  - Owns the main/window loop turn only.
  - Coordinates wait selection, event pump, typed host event dispatch, lower-owner mutation calls, and quit/continue control.
  - Must not own terminal render details, tab bar cell preparation, texture upload internals, scroll bar draw, pane layout construction, or tab lifecycle details.

- `howl-linux-host/src/host_input.zig`
  - Owns host-loop input admission and forwarding.
  - Owns input policy configuration, focus propagation, terminal input forwarding, window resize propagation, and cursor timer dispatch.
  - Must call terminal/tab/layout owners instead of importing bucket internals.

- `howl-linux-host/src/host_tabs.zig`
  - Owns host-main tab commands and active-tab selection routing.
  - Owns open tab, close tab, select tab, focus pane, split pane, active-tab problem handling, title aggregation, and paste routing.
  - Must use `howl-linux-host/src/tab.zig` and `howl-linux-host/src/tab_bar.zig`; it must not own texture resources or render ABI details.

- `howl-linux-host/src/host_present.zig`
  - Owns main/window present admission only, not rendering as a generic bucket.
  - Owns present-reason selection, conversion from ready owner outputs to `Layout.Frame`, and the final present submission call.
  - Does not own terminal, tab bar, or scroll bar surface turns. Each smaller surface owner runs its own turn independently and hands typed readiness/present facts upward.

- `howl-linux-host/src/term.zig`
  - Owns terminal surface turns directly.
  - Owns terminal render-turn sequencing currently in `bucket2.zig`: admission, prepare-needed drive, prepared terminal-surface extraction, submitted typed terminal texture acceptance, present-submitted tracking, present completion, and VT publish ack.
  - This owner is terminal-specific. It must not be named `surface`, `host_surface`, `manager`, `engine`, or `controller`.
  - It may keep using `howl-linux-host/src/render/surface_retained.zig` for retained terminal render state and `howl-linux-host/src/render/surface_layout.zig` for layout synchronization.

- `howl-linux-host/src/tab_bar.zig` and `howl-linux-host/src/tab_bar/*`
  - Own tab bar surface turns directly.
  - Own tab bar cell-surface preparation, revision handling, labels, and typed tab-bar present readiness.
  - Must not route through terminal render-turn code or a generic host-surface token.

- `howl-linux-host/src/texture/term.zig`
  - Remains the terminal texture presenter owner.
  - Owns upload of a terminal `HowlRenderSurfaceFrame` into one terminal GL texture slot and returns a typed terminal texture token.
  - Must not return or accept a generic `HowlRenderHostSurface` after the ABI cleanup.

- `howl-linux-host/src/texture/tab_bar.zig` plus `howl-linux-host/src/tab_bar/surface.zig` and `howl-linux-host/src/tab_bar/cell_surface.zig`
  - Own tab bar presentation as a bounded cell-text surface type.
  - Tab bar rendering must stay distinct from terminal rendering even though both use `HowlRenderSurfaceFrame` command emission.
  - Tab bar code must not route through terminal presenter slots, terminal turns, or a generic host-surface bucket.

- `howl-linux-host/src/texture/scroll_bar.zig`
  - Owns scroll bar presentation as its own surface type.
  - Today this surface type is GL-drawn and render-ABI-free. If it later gains a prepared render frame, that must be a scroll-bar-specific turn and typed token, not generic host-surface reuse.

Render ABI cleanup scope:

- Review `howl-render/include/howl_render.h`, `howl-render/src/libhowl_render.zig`, `howl-render/src/text/surface.zig`, `howl-render/src/surface/*.zig`, and host imports for stale nouns that imply one generic host surface owner.
- Preserve the C ABI boundary. Do not add Zig-shaped convenience APIs for host integration.
- Replace `HowlRenderHostSurface` with loosely coupled typed surface tokens. Do not rename it to one generic `HowlRenderHostTexture` and call the ABI clean.
- Use simple, pragmatic, consistent names. Expected direction:
  - `term_surface` for terminal render frames/tokens.
  - `tab_bar_surface` for tab bar render frames/tokens.
  - `scroll_bar_surface` only if scroll bar becomes a prepared render surface; today it is GL-drawn and should not receive a fake ABI token.
- Update all C declarations, Zig C imports, host aliases, tests, and stale grep gates in one implementation slice. No compatibility typedef or alias should remain because this is a private infant product.
- Remove misleading host aliases in Zig code: `render_retained.HostSurface`, `SubmitExecution.host_surface`, and local `host_surface` fields must become typed surface/token names where they cross from texture into retained render submission.
- Do not rename `HowlRenderSurfaceFrame` unless the user explicitly approves. Current source facts support it as the render-owned command/resource/damage frame emitted by `howl-render/src/surface/emitter.zig` and consumed by texture upload code.
- Do not merge `HowlRenderTextPrepare` and `HowlRenderCellSurfacePrepare`. Current code proves they are separate prepare inputs: VT text has render state, cursor cadence, focus, and cursor trail fields; cell surfaces have bounded cell text spans, explicit grid/cell sizes, and no VT render state.

`texture/surface.zig` decision:

- Current file: `howl-linux-host/src/texture/surface.zig` contains only `pub const Type = enum { term, tab_bar, scroll_bar };` and a small test.
- Current usage found no production dispatch through `Surface.Type`; only `texture/term.zig` mentions `surface.Type.term` in a comment and `texture.zig` re-exports the module.
- Decision: the enum is acceptable only as private texture presentation vocabulary, but currently too close to a bucket noun because it is unused as a dispatch contract.
- Preferred implementation choice: delete `howl-linux-host/src/texture/surface.zig` if no real dispatch table needs it after owner extraction.
- Acceptable narrowed alternative: keep it only if `texture/frame.zig` uses it as an internal compile-time/test assertion tying the three texture presenters to explicit draw/upload paths. It must not become a host-facing surface type registry and must not be imported by `host_loop.zig`, `host_present.zig`, `tab.zig`, or terminal runtime code.

What dies:

- Delete `howl-linux-host/src/buckets that must die/host_loop_bucket.zig` by the end of the accepted implementation slice.
- Delete the `Events.Processor` re-export from `howl-linux-host/src/events.zig` and make `howl-linux-host/src/main.zig` construct the true host-loop owner directly.
- Remove test imports of `host_loop_bucket.zig`, including `howl-linux-host/src/buckets that must die/bucekt2_test.zig` and `howl-linux-host/src/host_test_root.zig` embed-file stale checks against that bucket.
- Remove the misleading `activeSurface` helper from host-loop code. The active object is a runtime tab or terminal, not a generic surface.
- Remove `render_retained.HostSurface` in `howl-linux-host/src/render/surface_retained.zig`; replace it with terminal-specific typed token naming.
- Remove the generic C ABI `HowlRenderHostSurface` noun; replace it with the accepted typed tokens.
- Delete `howl-linux-host/src/texture/surface.zig` unless accepted implementation finds a real internal texture-only dispatch use.

What gets created:

- `howl-linux-host/src/host_loop.zig` for the main/window loop turn.
- `howl-linux-host/src/host_input.zig` for host input admission and forwarding.
- `howl-linux-host/src/host_tabs.zig` for host-main tab commands and active-tab routing.
- `howl-linux-host/src/host_present.zig` for present admission and layout-frame submission, only if it stays a present seam and not a broad render bucket.
- `howl-linux-host/src/term.zig` terminal turn methods and types for terminal render-turn sequencing currently trapped inside `bucket2.zig`.
- Typed render ABI/token edits in `howl-render/include/howl_render.h`, `howl-render/src/libhowl_render.zig`, `howl-render/src/text/surface.zig`, `howl-linux-host/src/render/surface_retained.zig`, `howl-linux-host/src/texture/term.zig`, `howl-linux-host/src/texture/frame.zig`, and tests.

Implementation cut order for a later accepted coding slice:

1. Add or move tests/comments first for the true owners and the ABI token seam.
2. Replace the stale generic `HowlRenderHostSurface` ABI and host aliases with typed, loosely coupled surface tokens.
3. Extract terminal render-turn sequencing from `bucket2.zig` into `src/term.zig` before renaming the terminal runtime type away from `Surface`.
4. Extract host present admission from `host_loop_bucket.zig` into `host_present.zig`, but keep per-surface turns in `term.zig`, `tab_bar.zig`, and scroll-bar/texture owners.
5. Extract host tab command routing into `host_tabs.zig`.
6. Extract host input/focus/resize/cursor dispatch into `host_input.zig`.
7. Extract the remaining main loop into `host_loop.zig` and update `main.zig` and `events.zig` imports.
8. Delete the dead bucket file and any unused texture surface enum file.
9. Run stale grep gates and verification gates before acceptance.

Non-goals:

- No product code changes before user acceptance of this artifact.
- No generic `host_render`, `surface`, `surface_type`, `host_surface`, `manager`, `engine`, `controller`, `context`, `state`, `options`, `facts`, or bucket replacement owner.
- No compatibility aliases, typedefs, shims, old-path re-exports, or fallback names.
- No new renderer architecture beyond the specific bucket and ABI seam cleanup.
- No movement of GL resource ownership out of `howl-linux-host/src/texture/`.
- No movement of PTY/VT ownership out of terminal/PTY/VT owners.
- No change that treats terminal, tab bar, and scroll bar surfaces as one generic host surface type or one generic host texture token.
- No change to pane/tab feature behavior, split UI, close behavior, cwd/commands, movement/transfer, floating/hidden behavior, or layout feature set.

Reviewer checklist:

- The accepted implementation deletes `howl-linux-host/src/buckets that must die/host_loop_bucket.zig`; it does not move or rename the bucket.
- No new generic `host_render.zig` bucket appears. If `host_present.zig` exists, it owns present admission only and delegates surface-specific work.
- Terminal render-turn code lives in `howl-linux-host/src/term.zig`, not under texture, tab, layout, or host-loop owners.
- Tab bar turn code lives under `howl-linux-host/src/tab_bar.zig` or `howl-linux-host/src/tab_bar/*`, not under terminal or host-present owners.
- Terminal texture upload remains in `howl-linux-host/src/texture/term.zig`.
- Tab bar cell-surface preparation remains tab-bar-specific and does not route through terminal texture presenter slots.
- Scroll bar drawing remains scroll-bar-specific and ABI-free.
- The C ABI boundary remains C-only and no host-facing Zig convenience API is introduced.
- `HowlRenderSurfaceFrame` remains render-owned command/resource/damage frame unless the user explicitly approves a rename.
- `HowlRenderTextPrepare` and `HowlRenderCellSurfacePrepare` remain distinct prepare inputs, and their submitted typed surface tokens remain distinct where submission needs a token.
- `texture/surface.zig` is either deleted or proven as texture-private dispatch vocabulary with no host-facing registry role.
- Tests prove present reason selection, layout-frame slicing, terminal upload-token submission, tab bar cell-surface bounds, and scroll layer drawing through the new owners.

Accepted user direction:

- `HowlRenderHostSurface` is broken into loosely coupled typed surfaces instead of renamed to one generic token.
- Surface type names use the existing Howl nouns exactly: `term_surface`, `tab_bar_surface`, and `scroll_bar_surface` if/when scroll bar needs a prepared render surface.
- Smaller surfaces own their own turns and run independently.
- `howl-linux-host/src/term.zig` owns terminal surface turns.
- `howl-linux-host/src/tab_bar.zig` and `howl-linux-host/src/tab_bar/*` own tab-bar surface turns.
- Scroll bar surface ownership stays scroll-bar-specific; it remains GL-drawn unless a future accepted slice gives it a typed prepared render turn.

Remaining risks and open questions for user approval:

- Exact C ABI spelling for the simple typed names, preserving C style while keeping the Howl noun: likely `HowlRenderTermSurface`, `HowlRenderTabBarSurface`, and future `HowlRenderScrollBarSurface` only if needed.
- `bucket2.zig` terminal runtime type `Surface` must not be renamed into a new copy of the old noun. Its old shape is cut apart into real existing owners until the bucket dies.
- Should `texture/surface.zig` be deleted outright as unused, or kept only if implementation creates an internal texture-private dispatch proof?
- Does the user want the older `sprints/host-loop-bucket-deletion.txt` edited to point here, or is this superseding artifact enough?
