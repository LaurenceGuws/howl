# Term Progress Scheduler Sprint

Purpose:

- Sharpen the existing per-terminal instance background thread owner.
- This sprint embodies Alacritty's PTY I/O loop / slave-side progress thread while preserving the product decision that one term instance has one background thread.

Scope:

- Reshape the current PTY wait/progress path under the true owner after research proves the file boundary.
- Candidate owner names are `pty/scheduler.zig` if PTY wait/drain remains the pacing primitive, or a tightly constrained terminal progress owner if the work is proven broader than PTY.
- Own PTY wait/drain/wake behavior and terminal instance progress done on that one thread.

Reference pressure:

- Alacritty `WindowContext` creates a PTY event loop on another thread so PTY I/O does not occupy renderer/input cycles.
- Alacritty terminal state is synchronized because the I/O loop updates state while display consumes it periodically.
- Current Howl has one per-terminal progress thread; this sprint sharpens that owner rather than splitting VT/render into new threads.

Non-goals:

- No extra VT thread.
- No extra render thread.
- No pane policy.
- No layout policy.
- No replacement bucket under `term`.

Proof requirements:

- Comments explain why this thread owns each progress decision and why the main thread does not.
- Tests prove bounded wait/drain cadence, wake coalescing, lifecycle handoff, and no pane-policy ownership.
- `zig fmt --check build.zig src`, `zig build check`, `zig build test:unit`, and `git diff --check` pass for every accepted slice.
