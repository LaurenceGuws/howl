Acknowledgement decision:

- Howl's texture trigger/global bit does not need an explicit acknowledgement message from main to PTY/VT/render owners in this sprint.
- Reason: the terminal/slave owner already completed terminal progress before setting the texture trigger. Main consuming the trigger only authorizes texture upload/present work under SDL cadence; it does not unlock further PTY/VT/render progress.
- Reason: `events/event_loop.zig:52-63` already coalesces wake pushes with `wake_queued`, and `events/event_loop.zig:108-112` rearms future wake pushes when the synthetic SDL wake is consumed. A second ack layer would duplicate this at the wrong owner boundary.
- Reason: Ghostty mailbox/wakeup edges above are notify/queue semantics without terminal-side ack on render scheduling; renderer/surface processing catches up independently.

No-ack trigger invariant:

- `texture/term.PresentTrigger.triggered == false` means no unconsumed terminal texture trigger is pending for that terminal instance.
- `triggerPresent` sets `triggered` true with acquire/release ordering and calls `EventLoop.wake()` only when the previous value was false.
- Repeated `triggerPresent` calls while `triggered == true` do not enqueue more SDL wakes and do not store per-event data.
- Main clears the bit only through `takeTriggered` while collecting texture-present work for a cadence-admitted turn.
- If terminal output changes again after main clears the bit, the next `triggerPresent` false-to-true transition wakes the main loop again.
- Clearing the bit is not an acknowledgement to PTY/VT/render. It only marks that main has observed the latest texture trigger state and may attempt upload/present.
- Main must be correct if a trigger is set concurrently while it is consuming the previous trigger: either the new trigger remains set for a later turn, or the current turn observes latest render state and a later trigger is coalesced by design. Worker must use atomic swap/exchange semantics that do not lose a false-to-true transition after clear.

Ack-if-needed rule, future only:

- If a future owner proves a resource cannot be reused until texture upload/present has consumed it, the acknowledgement belongs at the texture/render resource edge, likely `texture/term.zig` or `render/surface_retained.zig` present-resource ownership.
- That ack must not be main polling PTY/VT/render facts and must not be exposed as wake ack/query APIs on `term.zig`.
- No such ack is needed for this sprint because current render state/present bookkeeping already uses `notePresentSubmitted`/`completePresent` around submitted frames, and the new trigger only coalesces demand to attempt present.

## Correct Call Flow

PTY/term internal change to texture present:

1. `pty/wait_thread.zig` owns the slave/progress thread loop.
2. `pty/pump.zig` mutates PTY/VT/render state through `Term`; `progressRuntimeLocked` calls `term.render.notePrepareNeeded()` when VT runtime changes.
3. After owner-internal progress has completed, `wait_thread` observes `Outcome.should_redraw` and invokes a terminal texture-present signal.
4. `texture/term.PresentTrigger.triggerPresent()` sets a coalesced atomic trigger bit and calls `EventLoop.wake()` only on false-to-true.
5. `events/event_loop.zig` coalesces SDL wake events with `wake_queued`.
6. `events/event.zig` wakes when SDL cadence allows, consumes latest texture-present trigger state, builds frame data, runs render/texture upload/present path, and schedules frame cadence.
7. Consuming the texture trigger never calls `pty_pump.driveOnce`, never queries VT runtime due state, never queries PTY wake pending, and never drives cursor/render progress as terminal progress.

Main input flow:

1. Main drains SDL input through existing input/event loop paths.
2. Main publishes input to focused terminal/PTY owner path through existing `Tab.drainTextInputFastPath`, `Tab.drainPointerInput`, `Tab.handleScrollInput`, `term_input`, and `pty_session.publishInputBytes` paths.
3. Input publication does not create `RuntimeFacts` and does not synchronously drive PTY/VT/render progress.
4. The slave/terminal owner later observes resulting PTY/VT output through its internal scheduler and triggers texture present if output changes.
5. Host-local visuals caused by input, such as selection/link/scrollbar state already owned in the terminal surface bucket, may request host redraw only for host-local presentation. They must not call terminal progress.

Texture trigger semantics:

- Texture is the trigger; main SDL cadence is the cock.
- Multiple trigger pulls coalesce while the shot is still firing.
- If the trigger bit is not set and no input/window/layout work exists, main wake/cadence does nothing.
- Trigger consumption means texture upload/present/frame construction only.

Lifecycle semantics:

- `terminal_exited` is not a texture-present event unless it causes presentable texture work.
- Current lifecycle handling through `pty_session.outcome`/active-tab problem handling may remain if it does not depend on runtime facts.
- Async lifecycle event routing is deferred unless facts deletion exposes a concrete blocker.

## Sprint Scope Decision

Deleting `Surface.RuntimeFacts`, `Tab.RuntimeFacts`, and `LoopRuntimeFacts` is feasible in this sprint if and only if the texture trigger lands first in the same slice.

Reason:

- Without a texture trigger, deleting runtime facts leaves no owner-true path for slave-side terminal changes to trigger main-side texture/present work.
- The forbidden alternatives are main polling PTY wake pending, tab polling lower-owner facts, or moving the same bucket into `term.zig`.
- The texture trigger is not a replacement facts bucket: it is a single coalesced present trigger bit owned by `texture/term.zig`, with no VT/PTY/render/cursor facts and no per-event computation.

Therefore the worker should implement this as one sprint with two internal slices. If slice 1 cannot compile without retaining facts, stop before slice 2 and report the exact compile dependency.

## Exact Final Call Flow For Worker

PTY/slave output path:

- `pty_wait_thread.progressThreadMainWith` -> `Ops.driveProgress` -> `pty_pump.driveOnce` -> PTY/VT/render state mutation and `term.render.notePrepareNeeded()` -> return `Outcome.should_redraw = true` -> `target_value.term.triggerTexturePresent()` -> `texture/term.PresentTrigger.triggerPresent` -> `EventLoop.wake` coalesced by `wake_queued` -> main wakes on SDL cadence -> `tab.takeTextureTriggered`/event collection observes latest trigger -> `render(self)`/`tab.renderTurn`/`texture/term.uploadRenderSurface`/`texture/frame.submitPresentSync` -> frame cadence scheduling.

Main input path:

Frame cadence path:

- Present submission consumes a frame -> `events/scheduler.zig.Scheduler.requestFrame` schedules `.frame` by refresh interval -> `Scheduler.update` later appends `.frame_ready` -> main can present queued texture/host redraw work when frame is available.
