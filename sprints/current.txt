Hard doctrine for this sprint:

- Howl is currently wrong in this area. Behavior changes are expected when the current behavior exists only to preserve false owner boundaries.
- Proof is absent or wrong until rebuilt. Existing tests, comments, names, folders, and green builds are not proof that the shape is correct.
- Current shape is wrong until proven right. Owner boundaries, files, structs, thread loops, schedulers, comments, tests, ABI seams, and all call paths are in scope for redesign and remodeling.
- All Howl repositories are in scope: `howl-linux-host`, `howl-pty`, `howl-vt`, `howl-render`, host/vendor contracts, and ABI surfaces. Every touched boundary must be pristine, explicit, and proved.
- The target is exactly the reference-backed owner/thread shape below. Nothing more. Nothing less. No compatibility shims, no aliases, no stale design docs, no special avoidance code, and no partial old-path preservation.
- Comments are shape and ownership proof. They must explain what is happening here and why this owner performs the work. They must not be decorative citations like `kitty line 5 char 3`, and they must not preserve stale terms such as vague `runtime_facts` when the owner model has changed.

Reference-backed target owner/thread shape:

- Main host thread: `events/scheduler.zig` coordinates window events, frame cadence, redraw/dirty admission, wake coalescing, wait deadlines, and calls lower owners. This embodies Alacritty's UI/event/render scheduling thread using Howl nouns.
- Host structure owner: `layout/scheduler.zig` may exist as the Zellij `Screen`-derived pane/tab/layout mutation owner, but not as a generic manager and not necessarily as a thread. It owns queued split, focus, resize, hide/show, move, close, and pane creation admission when those mutations are planned.
- Term instance thread: the existing per-terminal instance background thread remains one thread. Its owner must be sharpened around PTY/terminal progress, not split into extra VT/render threads. This embodies Alacritty's PTY I/O loop / slave-side progress thread.
- `window/` owns OS window lifecycle. `texture/` owns texture resources. `events/scheduler.zig` coordinates them; window chrome does not own texture or render resource policy.
- Ghostty-style per-surface renderer and IO thread split is heavy pressure only. It is not copied unless a later proof shows Howl needs that cost.

Immediate accountability:

- Do not change `bucket2.zig` first. Redesign each caller to use `term.zig` and the existing true owner namespace.
- `term.zig` must remain a tiny terminal instance control spine. It is not a new bucket, surface, manager, runtime, or compatibility layer.
- Do not introduce `term-surface`, `terminal surface`, a second terminal instance type, or any replacement aggregate data shape.
- `Surface` remains only where already required by render/texture implementation or C ABI facts; no new host-facing surface noun is allowed.
- `layout/` owns tab, pane, split, window, visibility, focus, placement policy, and main-thread batching facts. It does not own VT, PTY, render contents, texture resources, GL, windows, or tab bar rendering.
- `texture/` owns main-thread GL presentation for the window. `texture/term.zig` is the texture owner's presenter for `surface_type.term`, not terminal-instance ownership. `src/term.zig` does not own GL, texture resources, layout batching, present submission, frame cadence, windows, tab bar, or non-terminal surface kinds.
- Everything below `src/term.zig` is built for the terminal instance directly: `vt/*`, `pty/*`, `render/*`, `texture/term.zig`, `input/*`, `scroll_bar.zig`, selection/link/cursor owners as they mature.
- Rendered terminal output may stay coordinated by `term.zig` for now. Perfecting the render-surface ownership boundary is explicitly deferred; do not invent a new noun to settle it prematurely.
