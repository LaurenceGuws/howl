Immediate accountability:

- Do not change `bucket2.zig` first. Redesign each caller to use `term.zig` and the existing true owner namespace.
- `term.zig` must remain a tiny terminal instance control spine. It is not a new bucket, surface, manager, runtime, or compatibility layer.
- Do not introduce `term-surface`, `terminal surface`, a second terminal instance type, or any replacement aggregate data shape.
- `Surface` remains only where already required by render/texture implementation or C ABI facts; no new host-facing surface noun is allowed.
- `layout/` owns tab, pane, split, window, visibility, focus, and placement policy. It does not own VT, PTY, render realization, textures, GL, windows, or tab bar rendering.
- `texture/term.zig` owns texture implementation details for the terminal instance. `src/term.zig` does not know GL, windows, tab bar, or non-terminal surface kinds.
- Everything below `src/term.zig` is built for the terminal instance directly: `vt/*`, `pty/*`, `render/*`, `texture/term.zig`, `input/*`, `scroll_bar.zig`, selection/link/cursor owners as they mature.
- Rendered terminal output may stay coordinated by `term.zig` for now. Perfecting the render-surface ownership boundary is explicitly deferred; do not invent a new noun to settle it prematurely.
- For event-loop/runtime/progress/presentation work, copy Alacritty's control-flow shape, not its nouns.
- Use event-driven multiplexers to fill Alacritty's single-terminal gaps:
  - Zellij first for pane/tab policy and pane-info facts.
  - tmux for mature pane/window/session lifecycle and layout verbs.
  - WezTerm for event-driven mux/window/tab/pane API pressure.
- Howl nouns remain mandatory: `window`, `tab`, `pane`, `term`, `pty session`, `vt surface`, `render surface`, `texture`, and `frame`.
- Do not introduce Alacritty nouns such as `Display` or `Context` into Howl.
- The event loop consumes and orchestrates all eligible live `Term` instances through tab/pane policy. It does not own VT, PTY, render, texture, layout, or terminal-local internals.
- Execute every slice in this order:
  1. write or preserve policy comments, knobs, options, invariants, assertions, and failing tests first
  2. route the caller through `term.zig` and the true owner namespace
  3. delete the now-unused bucket method/field/path
  4. run `zig fmt --check build.zig src`, `zig build check`, `zig build test:unit`, and `git diff --check`
  5. commit host first, then root pointer/accountability if requested or if workflow requires it
- Every handoff must preserve these non-goals:
  - no bucket move or rename
  - no bucket beautification
  - no new surface noun
  - no C/render ABI change unless explicitly planned and receipted
  - no compatibility aliases/shims
  - no broad feature work: pane close, resize UI, more panes, cwd/custom commands, movement/transfer, floating/hidden behavior, tab transfer
