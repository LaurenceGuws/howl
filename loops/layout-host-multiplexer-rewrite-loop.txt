Scoping statement:

- The active sprint is to rewrite `howl-linux-host/src/layout/` into the host structure layer for tabs, panes, splits, scrollbar, and scroll chip.
- `window/` owns SDL window creation and OS-window lifecycle.
- `layout/` owns the interior structure of the window created by `window/`.
- `layout/` is the HTML/CSS layer for host composition.
- `layout/` must not use VT nouns such as `viewport` or `screen` for host structure.
- `layout/` must follow terminal multiplexer pressure first for this slice: tmux `session/window/pane/layout` and zellij `tab/pane/layout`.
- Ghostty `Surface` remains a reference for the terminal widget concept, but it is not the top naming pressure for this slice.
- The rewrite must make panes loosely coupled from placement so panes can move across splits, tabs, and windows, and can become tiled, floating, hidden, or shown while retaining accurate placement facts.
- Tabs must be able to move between windows.
- Floating panes must be able to hide/show while preserving correct geometry and identity.

- Single-agent direct collaboration.
- This is a strict sprint, not a casual rename pass.
- Execution proceeds only through the accepted staged contract below.

Non-negotiables:

- `window/` owns SDL windowing only.
- `layout/` owns host structure only.
- No fake `viewport` owner survives sprint exit.
- No VT `screen` ownership leaks into host structure.
- No bucket owners, `Context`, `Info`, `Request`, `Snapshot`, or compatibility glue.
- Pane identity must be placement-independent.
- Split structure must reference pane ids/handles rather than embedding pane runtime state.
- End-of-sprint state must be owner-true, testable, grep-clean for stale layout lies, and fit future split/tab/window transfer work.
