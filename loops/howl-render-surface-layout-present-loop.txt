Problem statement:

- Howl currently uses overlapping render nouns: `surface`, `scene`, `geometry`, and `grid` across `howl-render`, `howl-linux-host`, and the render C ABI.
- Those nouns are not presumed correct. Existing APIs and cross-repo contracts are not frozen.
- The sprint must produce the reference-backed owner model first, then execute owner-true code/API slices without preserving stale names for compatibility comfort.
- Linux Wayland is the first host scope, with KDE Wayland-only and Hyprland as the practical target environments. X11 is not an implementation target for this sprint.
- SDL remains the pragmatic window/input/text-input/clipboard/event harness unless research proves it blocks the required GPU-present control.
- SDL's normal `SDL_GL_SwapWindow` hides the EGL swap-damage hook; SDL still exposes EGL display, EGL window surface, and EGL proc lookup APIs that may allow a small direct damaged-present path.

Non-negotiables:

- Alacritty governs host display, damage, renderer organization, and Wayland EGL present-damage shape unless the user explicitly overrides a specific case.
- Ghostty contributes VT and embedding seam pressure, not broad renderer/display architecture when Alacritty has a direct shape.
- Kitty contributes GLFW/Wayland/EGL and UX pressure where Alacritty or SDL facts leave a gap, but Kitty does not override Alacritty for the display/render owner split.
- TigerBeetle style is a hard gate for exact nouns, owner truth, assertions, bounded arrays/queues, and proof.
- API and ABI names are in scope; no cross-repo API is frozen.

- Do not implement X11 fallback during this sprint.

Initial reference facts already established in this session:

- Alacritty tracks terminal `LineDamageBounds` and `TermDamage`, imports that into display `DamageTracker`, shapes damaged lines into pixel `Rect`s, overdamages for nearby/wide cells, merges overlapping rects, draws normally, and on Wayland EGL calls `swap_buffers_with_damage` at present time.
- Alacritty's partial GPU update is a present-damage hint, not a retained partial render command stream.
- SDL3 docs expose `SDL_EGL_GetCurrentDisplay`, `SDL_EGL_GetWindowSurface`, and `SDL_EGL_GetProcAddress`.
- SDL3 Wayland `SDL_GL_SwapWindow` calls plain `eglSwapBuffers` in `src/video/wayland/SDL_waylandopengles.c`; it has no public damage-rect parameter.
- Early `howl-linux-host` had a `-Dwindow-backend=sdl|glfw` compile-time backend seam; Kitty vendors a modified GLFW, but its normal GLFW EGL swap path also uses plain `eglSwapBuffers`.
