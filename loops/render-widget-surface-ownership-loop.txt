# Render Widget Surface Ownership Loop

Active roles:

- Orchestrator/reviewer: main agent.
- Teammate: combined researcher/coder, but researcher-only until the written plan is reviewed and accepted.

Loop:

1. Researcher writes `research/render-widget-surface-ownership.md` with source-backed findings, stale names, exact owner targets, first slice, risks, and proof gates.
2. Orchestrator/reviewer audits the research artifact against the sprint contract, references, vocabulary, ABI boundary, and bucket deletion rule.
3. If accepted, orchestrator seeds coder with exactly one implementation slice.
4. Coder changes product code only for the accepted slice and reports changed paths, proof, and gaps.
5. Orchestrator/reviewer audits the diff before acceptance and commit.
6. Repeat until the sprint has no stale render god-surface nouns and no tab-bar or scroll-bar surface control in `bucket2.zig` or `src/term.zig`.

Stop conditions:

- Reference conflict without a recorded user override.
- A plan that preserves generic surface worldview.
- Any implementation that moves bucket control into `src/term.zig` instead of the true widget owner.
- A fix that weakens resource lifecycle assertions instead of making ownership exact.
