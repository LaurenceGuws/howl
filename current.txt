# Current Slice: Point 5 Host Frame Pacing

- promoted item: `Point 5: Host Frame Pacing Is Under-Shaped`

## Accepted Answer

- The host now has explicit wake/redraw/render/present/completion concepts, but frame pacing itself is still under-shaped.
- Terminal render desire is still treated like loop admission/pacing state.
- The host needs a first-class frame pacing state that owns blocking, render permission, and present submission permission.
- Frame pacing must remain host policy in `main.zig`; do not move it into terminal, render, or input owners.

- TigerBeetle requires bounded explicit host-side state transitions.

## Exact Change Shape

- In `howl-linux-host/src/main.zig`
  - add `FramePacingState` with exactly:
    - `redraw_requested: bool`
    - `render_work_pending: bool`
    - `frame_permit_ready: bool`
    - `present_in_flight: bool`
    - `present_complete_pending: bool`
  - `FramePacingState` must be the only owner of:
    - blocking decision

    - `.terminal_retire` must not create unmatched present tokens
