## Required Product Shape

- Keep the realizer internal-only.
- Validate lifetime with frame order, not by treating any retire span as making the
  resource retired for the whole frame.
- A resource may be created, uploaded, used by commands, then retired later in the
  same frame.
- Upload after retire must reject.
- Command use after retire must reject.
- Retire before the final command that reads the resource must reject.
- Duplicate retire must reject.
- Wrong generation must stay distinguishable from missing resource.
- Existing clear/fill/sprite/alpha-glyph behavior must remain unchanged.
- No heap allocation inside realization.

## Required Tests

Add or update unit tests with exact intent equivalent to these names:

- `protocol v0 realizer accepts sprite use before same frame retire`
- `protocol v0 realizer rejects sprite use after same frame retire`
- `protocol v0 realizer rejects upload after same frame retire`
- `protocol v0 realizer accepts glyph atlas use before same frame retire`
- `protocol v0 realizer rejects glyph atlas use after same frame retire`

Existing duplicate retire, retired sprite use, retired glyph atlas use, wrong
generation, and upload-before-create tests must keep passing with meaningful
errors.

## Required Invariants

- All lifetime validation completes before caller-visible pixel mutation for a
  rejected frame.
- Order checks must be explicit and bounded by V0 span maxima.
- Resource lifetime remains create, update, use, retire, ack, reuse.
- Same-frame retire means retired after all preceding commands and uploads, not
  retired from the beginning of the frame.
