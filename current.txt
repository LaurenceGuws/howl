## Required Product Shape

- Add host-side V0 resource-plan validation/accounting for the borrowed frame:
  creates, uploads, command resource uses, and retires.
- Planning is read-only and turn-local. It must not retain the frame pointer, span
  pointers, upload byte pointers, command pointers, or backend-resource identities.
- The plan must be bounded by existing V0 ABI maxima and record bounded accounting:
  success count, failure count, last status, create/upload/use/retire counts, and
  upload byte count.
- Unsupported commands/resources must fail the plan probe only; they must not affect
  the actual RGBA upload/submit path.
- The existing software oracle probe must remain intact.

## Required Tests

Add narrow host tests with exact intent equivalent to:

- `host retained render plans protocol v0 resource lifecycle`
- `host retained render plan rejects upload before create`
- `host retained render plan rejects use after retire`
- `host retained render records resource plan accounting`

Use pure helper tests. Do not introduce GL/resource realization harnesses.

## Required Invariants

- All loops are bounded by validated V0 span counts and ABI maxima.
- Resource use is visible only when create_seq <= command index < retire_seq.
- Upload is visible only after create_seq and before retire_seq.
- Planning has no caller-visible host pixels or GL state mutation.
- Existing prepared upload result and submit path remain full RGBA.
- Counters saturate or are otherwise bounded.
