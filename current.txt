Owner: `howl-linux-host` terminal render-turn lock boundary.

Research inputs:

Purpose:

- Match the recorded Alacritty runtime boundary: collect/copy terminal-render state
  under `term.mutex`, release the lock, perform host/backend GL work, then relock only
  for render submit state transition.
- Remove V0 realization, GL state sampling, full RGBA host upload, and diagnostic
  printing from the terminal mutex critical section.

## Required Shape

- Locked phase: source publication, render action selection, prepare if needed,
  `preparedUpload()` extraction, and scalar submit metadata copy.
- Unlocked phase: V0 texture realization, GL state sampling, `term_texture.ensureSurface()`,
  `term_texture.uploadPreparedBuffer()`, and diagnostic printing.
- Relocked phase: `term.render.submit()`, retained render state transition,
  `term_texture` submit result update, and render turn result.

## Hard Invariants

- No `term_texture.*` calls while `term.mutex` is held.
- No `protocol_v0_textures.realizeFrame()` while `term.mutex` is held.
- No `term_texture.sampleGlState()` while `term.mutex` is held.
- No `std.debug.print()` diagnostics from the submit path while `term.mutex` is held.
- `term.render.prepare()`, `term.render.preparedUpload()`, and `term.render.submit()`
  remain under `term.mutex`.
- Borrowed prepared frame/span/upload byte pointers are consumed synchronously in the
  same owner turn and are never retained.
- The retained prepared handle must not be released, replaced, forgotten, or submitted
  by another path between unlock and relock.

## Required Tests

- A fake/test path proves backend realization/upload callbacks observe the terminal
  mutex unlocked.
- A test proves render submit still happens under lock after backend upload.
- A test proves host upload failure returns failed submit result without leaking the
  prepared upload wrapper.
- Existing present-pending and present-completion tests still pass.

- Stop if moving backend work out of lock requires render ABI or V0 protocol changes.
