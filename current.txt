# Current Slice: Render Protocol V0 Persistent Sprite Resource Emission Probe

Owner: `howl-render` protocol V0 emission and retained protocol resource state.

Sprint scratchpad and contract:

- `research/2026-05-31-howl-render-protocol-sprint.md`
- `docs/render-protocol-v0.md`

Purpose:

- Replace same-frame disposable prepared sprite V0 resources with persistent
  render-owned sprite resources.
- Emit create/upload only when a sprite resource is first observed or materially
  changes.
- Emit later commands referencing existing live resources without create/upload/retire.
- Keep full RGBA as visible fallback/oracle.

## Exact Change Scope

Allowed files:

- `howl-render/src/protocol_v0/emit.zig`
- `howl-render/src/protocol_v0/realize.zig` only if retained oracle support is needed
- Existing `howl-render/src/prepared/**` or session/protocol owner files only if they
  are the true owner for retained protocol resource state
- Existing howl-render protocol tests
- `research/2026-05-31-howl-render-protocol-sprint.md`

No C ABI/header changes. No host changes. No ack/removal ABI. No V0 command drawing
or presentation replacement. No full RGBA deletion.

## Required Product Shape

- Render owns opaque nonzero V0 sprite resource IDs.
- Numeric resource values are monotonic and are not reused in this slice.
- Generation remains `1` for first lifetime only; no retire/reuse path is introduced.
- Persistent sprite resources emit create/upload once, then later frames emit commands
  referencing the existing live resource.
- Normal persistent sprites emit no retire in this slice.
- Internal sprite lookup may use current render-owned sprite facts, but must not expose
  `SpriteKey` as public ABI glyph identity.
- Resource capacity or upload-bound exhaustion fails closed to full RGBA fallback/oracle
  without mutating accepted V0 payload/resource state.
- The V0 software oracle/resource store must be retained enough to prove later-frame
  commands can reference earlier-frame resources byte-equivalent to the full RGBA
  prepared buffer.

## Required Tests

- Frame 1 with a sprite emits create/upload/command and no retire.
- Frame 2 with the same source-backed sprite identity emits command only for the same
  resource ID.
- Different source-backed sprite identity or incompatible bytes/dimensions emits a
  distinct monotonic resource ID, not numeric reuse.
- Capacity or upload-bound exhaustion fails closed without mutating accepted V0
  payload/resource state.
- Retained software realizer/oracle proves frame 2 byte-equivalent to
  `prepared_buffer.compose()` while using a prior-frame resource.
- Existing root `zig build test` and `zig build check` pass.

## Stop Conditions

- Stop if stable sprite identity cannot be defined from current render-owned facts
  without guessing.
- Stop if eviction/reclamation is required; that needs ack/removal and is later.
- Stop if this requires C ABI/header changes.
- Stop if this requires host changes, V0 command drawing, presentation replacement, or
  deleting full RGBA.
- Stop if resource ownership cannot live in a true render owner without host/backend
  policy leaking into render.
