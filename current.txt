## Required Product Shape

- Add an internal-only V0 emitter module.
- Emitter input is explicit prepared consequences or test fixtures; do not reach
  through host/backend state.
- Emitter output owns storage for C ABI frame spans: creates, uploads, commands,
  retires, damage, glyph refs, and upload bytes as needed by tests.
- Use shipped C ABI structs and macros through `ffi.zig`; do not duplicate ABI
  structs or constants.
- Emit command order matching `prepared/buffer.zig` pass order for supported consequences.
- Support only clear/fill/sprite consequences in this slice.
- Sprite resources use explicit create/upload/use/retire order in the documented
  command-boundary domain. Retire each temporary sprite resource after its final
  sprite command use with `retire_seq = final_command_index + 1`.
- Emission failure must fail closed without mutating already-accepted output.
- The existing full RGBA composition remains the oracle and fallback.

- All span counts must be checked against the named V0 maxima before use.

  `HOWL_RENDER_V0_UPLOAD_BYTES_MAX`.
- Resource IDs are render-owned within emitted storage; creates precede uploads,
  uploads and creates are visible before use, and retires occur after final use.
- No command references a missing resource.
- No backend object, texture ID, GL type, host pointer, or event-loop policy enters

- Emitter storage owns span memory long enough for the returned frame view.
- Tests must realize emitted frames through `protocol_v0.realize()` and compare
