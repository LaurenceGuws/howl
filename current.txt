# Current Slice: PNG EBADPNG Protocol Errors

Owner: workspace root.

Sprint scope: graphics.

Promoted from `graphics-machinery-scratchpad.md` after PNG/error parity research.

## Goal

Return Kitty-style `EBADPNG` protocol failures for invalid `f=100` PNG payloads instead of asserting or collapsing into generic data errors.

## Target Files

- `howl-vt/src/kitty/graphics.zig`
- `howl-vt/src/test/terminal_graphics.zig`

## Required Behavior

- Invalid direct `f=100` PNG upload replies with `EBADPNG:*` and does not store image data.
- Invalid `f=100` query replies with `EBADPNG:*` and does not store image data.
- PNG size/decode helpers return explicit errors instead of asserting or using `unreachable` for stb failures.
- Valid PNG behavior already covered by existing tests remains green.

## Hard Constraints

- Do not change ABI, render, host, parser, or terminal files.
- Do not replace stb_image or add libpng.
- Do not broaden into full PNG mode/color-management/gamma/ICC parity.
- Do not add PNG zlib support.
- Do not change indirect media lifecycle, animation, quiet, delete/reset, quota, composition, or generated placeholder behavior.
- Do not special-case yazi/panes.
- Keep the smallest correct diff.

## Required Tests

- Invalid direct PNG upload returns `EBADPNG` and leaves image count unchanged.
- Invalid PNG query returns `EBADPNG` and leaves image count unchanged.
- Valid simple PNG decode/current-frame publication remains covered by existing PNG tests or an added focused test if needed.

## Verification Required

- `zig build test` in `howl-vt`
- `zig build test:regression:build` in `howl-vt`
- `git diff --check` at workspace root

Stop condition:

- If correct behavior requires replacing the PNG decoder, broad image cache redesign, render changes, ABI changes, or a full PNG color-management matrix, stop and report the exact dependency instead of widening the slice.
