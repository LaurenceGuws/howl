## Required Product Shape

- Add an internal owner-owned V0 payload field to `prepared_owner.Owner`.
- Initialize it during `Owner.create()` after `PreparedSurface` is assigned and
  before handle registration.
- Use `protocol_v0.emit.emitPrepared()` semantics and owner-owned storage.
- Keep V0 storage immutable while the prepared handle is live.
- Deinitialize V0 storage in `deinitPayload()` with the same lifecycle as
  `PreparedSurface` and `rgba_pixels`.
- If V0 emission fails, `Owner.create()` must fail before registering a prepared
  handle and must release any allocated RGBA/V0 payload already created.
- Do not expose the V0 frame through C ABI or host path in this slice.

## Required Tests

Add protocol proof tests with exact intent equivalent to:

- `protocol v0 prepared owner frame equals owner rgba oracle`
- `protocol v0 prepared owner releases v0 payload with handle`
- `protocol v0 prepared owner create fails closed when v0 emission fails`

Tests must realize owner-owned V0 through `protocol_v0.realize()` and compare every
byte to `Owner.rgba_pixels` or the same `prepared_buffer.compose()` oracle. Do not
use a local duplicate oracle.

## Required Invariants

- Owner-owned V0 span pointers and upload byte pointers remain valid for the live
  prepared handle.
- Owner cleanup cannot leak V0 upload bytes or stale frame spans.
- Existing prepared handle state transitions remain unchanged.
- `Owner.buffer()` and host-facing upload behavior continue to return full RGBA.
- Full RGBA remains the oracle/fallback.
