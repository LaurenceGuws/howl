## Required Product Shape

- Add a host-side software V0 realization helper for the command/resource subset
  currently emitted by render prepared frames: clear, fill, and sprite.
- The helper must consume the borrowed V0 frame during the submit turn only.
- Compare realized bytes to the prepared RGBA buffer and record bounded accounting:
  success count, mismatch/failure count, last failure reason, and checked byte count.
- Do not retain the frame pointer, span pointers, or upload byte pointers.
- Do not change the existing full RGBA upload path or submit result.
- Reject unsupported V0 commands/resources in the software probe without affecting
  the actual RGBA path.

## Required Tests

Add narrow host tests with exact intent equivalent to:

- `host retained render software realizes protocol v0 fill frame`
- `host retained render software realizes protocol v0 sprite frame`
- `host retained render software probe detects rgba mismatch`
- `host retained render software probe rejects unsupported command`
- `host retained render records software probe accounting`

Use pure helper tests if live host prepared-handle setup would require GL/resource
realization. Record the harness gap if so.

## Required Invariants

- Software probe validates all byte lengths before reading/writing.
- No caller-visible host pixels or GL state are mutated by the software probe.
- Existing prepared upload result and submit path remain full RGBA.
- All counters saturate or are otherwise bounded.
