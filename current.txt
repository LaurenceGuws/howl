# Current Slice: Point 6 Strong Present Completion

Owner: `howl-linux-host`.

- promoted item: `Point 6: “Present Complete” Is Not A Strong Host Concept Yet`

## Accepted Answer

- Present completion is now named in `main.zig`, but it is still not a strong host concept.
- The window backend submit path should return a host-owned present token.
- Completion should be drained explicitly from the window owner path, then matched against terminal retained present state.
- Terminal retained state should remember both the submitted terminal snapshot and the host present token.
- Host code must separate present submission from present completion; completion must not happen in the same statement block as submit.

## Exact Change Shape

- In `howl-linux-host/src/window/present.zig`
  - add `pub const PresentToken = u64`
  - extend `Present.State(c)` with:
    - `next_present_token`
    - `submitted_present`
    - `completed_present`
  - replace `present(...) void` with:
    - `submitPresent(...) PresentToken`
    - `drainPresentComplete(...) ?PresentToken`
  - assert single in-flight token and drain-before-overwrite semantics
- In `howl-linux-host/src/window/window.zig`
  - replace `State.present(frame)` with:
    - `State.submitPresent(frame) PresentToken`
    - `State.drainPresentComplete() ?PresentToken`
- In `howl-linux-host/src/terminal/render/retained.zig`
  - replace `present_in_flight: ?u64` with a struct carrying:
    - `snapshot_seq`
    - `token`
  - replace:
    - `beginPresent(snapshot_seq)`
    - `finishPresent() ?u64`
  - with:
    - `notePresentSubmitted(snapshot_seq, token)`
    - `completePresent(token) ?u64`
- In `howl-linux-host/src/main.zig`
  - submit path records the token on terminal present reasons
  - completion path drains window completion and passes the token to terminal completion
  - host must never call terminal completion in the same statement block as submit
  - preserve Point 2 `PresentReason` semantics:
    - `.host_damage` submits a host present and does not consume terminal retained present state
    - `.terminal_frame` and `.terminal_retire` submit host present and later complete terminal retained present state by matching token

## Required Proof

- `window/present.zig` tests for:
  - submit returns monotonic nonzero tokens
  - single in-flight submission is enforced
  - completion drains exactly once before overwrite
- `terminal/render/retained.zig` tests for:
  - submit token storage
  - matching completion returns the snapshot sequence
  - mismatched completion is rejected or ignored without clearing state
  - pending-state lifetime survives until matching completion
- `main.zig` fake-window/fake-tab tests proving:
  - submit and completion are distinct host actions
  - `.host_damage` completion does not call terminal completion
  - terminal present reasons complete only after a drained matching token
- Existing Point 2 and Point 3 tests must keep passing.
