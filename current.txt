# Current Slice: Animation Runtime Edge Cases

Owner: workspace root.

Sprint scope: graphics.

Promoted from `graphics-machinery-scratchpad.md` after animation runtime parity research.

## Goal

Match Kitty animation runtime edge cases for loading mode, finite loop counts, and gapless frames.

## Target Files

- `howl-vt/src/kitty/graphics.zig`
- `howl-vt/src/test/terminal_graphics.zig`

## Required Behavior

- `s=2` loading mode waits on the last available frame when no future frame exists.
- If the last-frame deadline has already passed, `s=2` advances immediately when a future frame arrives.
- Finite `v>1` runtime looping completes the requested repeat count and does not stop before the first wrap.
- Frames with gap `0` from negative `z` remain stored but are skipped by runtime publication.
- Runtime publication continues to update current-frame payloads through VT-owned state only.

## Hard Constraints

- Do not change ABI, render, host, parser, or terminal files.
- Do not change frame upload gap parsing semantics already implemented.
- Do not change quiet response handling, delete/reset behavior, quota, composition, or generated placeholder publication.
- Do not implement host presentation cadence or render-side animation policy.
- Do not broaden into decoded/cache storage or PNG behavior.
- Do not special-case yazi/panes.
- Keep the smallest correct diff.

## Required Tests

- Loading animation advances immediately when a future frame arrives after waiting at the last available frame.
- Finite `v=2` two-frame animation publishes frame sequence `1 -> 2 -> 1 -> 2` before stopping on the next wrap attempt.
- Gapless negative-`z` frame is skipped by runtime publication while remaining stored.

## Verification Required

- `zig build test` in `howl-vt`
- `zig build test:regression:build` in `howl-vt`
- `git diff --check` at workspace root

Stop condition:

- If correct behavior requires host/runtime presentation policy, render changes, ABI changes, decoded/cache storage, or broader animation scheduling, stop and report the exact dependency instead of widening the slice.
