Issue 6:

- Kitty graphics truth is exported above VT, but the next blocker is still inside VT owner truth.

Current state:

- VT owns the supported physical subset and exports graphics meta, indexed image query, indexed placement query, payload copy, and cell pixel size.
- Host pairs `copy_surface()` with `query_graphics_meta()` and retries on stale item publication.
- Render ingests copied image/placement metadata and proves replacement follows graphics publication truth.
- No drawing is implemented.

Active blocker:

- Current VT truth is still false for implicit-size placements.
- `effective_columns` / `effective_rows` are not Kitty-honest for:
  - `c=0,r=0`
  - `c>0,r=0`
  - `c=0,r>0`
- That false extent already affects VT-owned mutation behavior, not just ABI publication.

Current rule:

- `copy_surface()` and graphics item queries are separate publications.
- Surface uses `snapshot_seq`.
- Graphics items use `publication_seq` from `query_graphics_meta()`.
- If any item query rejects the publication, restart the whole acquisition attempt.

Next checkpoint:

`VT Destination-Extent Truth`

What must be true:

- VT must own truthful current destination extent for implicit-size placements.
- Above-VT code must be able to derive viewport inclusion and clipping without guessing.
- No render-owned geometry may leak back into VT truth.

Contract direction:

- Keep requested `columns` / `rows`.
- Add or redefine current resolved destination truth explicitly, likely:
  - `dest_left_cell_px`
  - `dest_top_cell_px`
  - `dest_right_cell_px`
  - `dest_bottom_cell_px`
  - `dest_grid_columns`
  - `dest_grid_rows`

Proof target:

1. Kitty-honest resolution for:
   - `c=0,r=0`
   - `c>0,r=0`
   - `c=0,r>0`
   - `c>0,r>0`
2. Non-zero offsets.
3. Cursor movement uses resolved grid extent.
4. Viewport inclusion/clipping derives from resolved truth without guesses.
5. No render-owned geometry leaks into VT.
