- promoted item: `Point 2: Present Cadence Is Not First-Class Enough`

## Accepted Answer

- Present cadence is still under-expressed after Point 3 made present submission and completion explicit.
- The host must own a named presentation contract rather than deriving a bare submit boolean through `shouldPresent(...)`.
- Host-only damage, terminal frame publication, and terminal present retirement are distinct present reasons.
- Terminal present completion must happen only for terminal-owned present reasons, not for host-only damage.

Reference-derived truth:

- Alacritty has explicit host frame cadence primitives and keeps draw/present scheduling in host policy.
- Ghostty separates render actions from present/wakeup actions.
- TigerBeetle favors explicit state machines over booleans with hidden lifecycle meaning.

## Exact Change Shape

- In `howl-linux-host/src/main.zig`
  - delete `shouldPresent(...)`
  - add exactly:
    - `const PresentReason = enum { none, host_damage, terminal_frame, terminal_retire };`
    - `const PresentPlan = struct { reason: PresentReason, needs_render_turn: bool };`
  - replace bare `PresentIntent.submit: bool` with present reason/plan policy
  - add `fn derivePresentReason(host_redraw: bool, step: TerminalPanel.TurnStep) PresentReason`
  - present submission must switch on `PresentReason`
    - `.none`: no present, no terminal completion
    - `.host_damage`: present, no `tab.finishPresent()`
    - `.terminal_frame`: present, then `tab.finishPresent()`
    - `.terminal_retire`: present, then `tab.finishPresent()`
  - `TerminalPanel.TurnStep` remains terminal/render-owned fact
  - host must own present cadence policy in `main.zig`, not in `TerminalPanel` or `window/present.zig`

## Required Proof
