# Current Slice: Point 8 Text Input Fast Path

Owner: `howl-linux-host`.

Source scratchpad:

- `host-alacritty-gap-scratchpad.md`
- promoted item: `Point 8: The Simple Text Path Is Not Obviously Collapsed`

## Accepted Answer

- The simple readline/text path is not readable as a primary path.
- Text input currently joins the generic input queue and is drained beside pointer, scroll, hover, selection, and host UI behavior.
- Host control/pacing is now explicit enough to split terminal text publication from pointer/UI handling.
- This slice is host-only. Do not implement VT protocol support for `OSC 133` or `DECSCUSR` here; record that as future VT-owner work if needed.

Reference-derived truth:

- Ghostty queues render after output processing.
- Alacritty wakes after terminal mutation and keeps low-latency frame events visible.
- Alacritty content/damage model makes the simple text path primary, not buried in pointer/UI policy.

## Exact Change Shape

- In `howl-linux-host/src/terminal/terminal_panel.zig`
  - split `drainInput(...)` into exactly:
    - `drainTextInputFastPath(self: *TerminalPanel, input_events: *HostInput) DrainInputOutcome`
    - `drainPointerAndUiInput(self: *TerminalPanel, input_events: *HostInput, origin_x: i32, origin_y: i32, logical_width: c_int, logical_height: c_int) DrainInputOutcome`
  - `drainTextInputFastPath` must handle only:
    - `.bytes`
    - `.key`
  - `drainTextInputFastPath` may call only:
    - `publishTerminalBytes`
    - `publishTerminalKey`
    - `resetCursorBlinkActivity`
  - `drainTextInputFastPath` must not touch host redraw, selection, hover, scroll, mouse, or window policy.
  - Pointer/UI handling remains in `drainPointerAndUiInput`.
  - Keep `DrainInputOutcome` semantics: PTY publication and host visual mutation stay distinct.
- In `howl-linux-host/src/main.zig`
  - `forwardTerminalInput()` must call text fast path first, then pointer/UI path.
  - No host policy step may be inserted between text publication and runtime progress.
