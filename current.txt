# Current Slice: Render Placeholder Path Deletion

Owner: workspace root.

Sprint scope: graphics.

Promoted from `graphics-generated-placement-transition-scratchpad.md` atomic commit sequence item 4.

## Goal

Remove render-owned Kitty Unicode-placeholder interpretation now that VT publishes generated placeholder cells as normal graphics placements.

## Target Files

Render:

- `howl-render/src/frame/surface_buffer.zig`
- `howl-render/src/frame/graphics_prepare.zig`
- `howl-render/src/frame/surface_text.zig`
- `howl-render/src/frame/surface.zig`
- `howl-render/src/frame/queue.zig`
- tests under `howl-render/src/frame/`

## Required Behavior

- Generated placeholder placements render through the normal placement path.
- `z_index == -1` still classifies generated placeholder placements below text.
- Render no longer parses Kitty placeholder cells, placeholder diacritics, foreground image ids, underline placement ids, or virtual placement semantics.
- Render keeps rejecting mixed generated-placeholder placements plus non-empty placeholder-run spans until placeholder-run ABI plumbing is removed in a later host cleanup slice.
- Normal image decode, bind, prepare, sort, and draw behavior remains intact.

## Hard Constraints

- Do not edit VT in this slice unless a compile blocker proves otherwise.
- Do not add a new render-side placeholder drawer or placeholder-specific geometry path.
- Do not remove normal raster decode/bind machinery.
- Do not reintroduce generated placement plus placeholder-run double draw.
- Do not special-case yazi/panes.

## Verification Required

- `zig build test` in `howl-render`
- `zig build test:unit` in `howl-linux-host`
- `git diff --check` at workspace root

Stop condition:

- If render cannot draw generated placeholder placements as normal placements without needing Kitty placeholder protocol data, stop and report the exact ABI gap. Do not keep a fallback placeholder interpreter.
