# Current Slice: Graphics Decoded Quota Eviction

Owner: howl-vt.

Sprint scope: graphics.

## Goal

Make VT decoded graphics bytes the primary protocol storage quota while keeping
legacy/base64 bytes as a conservative compatibility bound.

## Strategic Goal

Continue the graphics cleanup loop autonomously until Howl's graphics machinery is
cleaner and more accountable than Kitty's, without fake progress. Every step must remain
source-backed, bounded, tested, reviewed, verified, and committed.

## Source Findings

- Kitty and Ghostty account decoded image data as storage truth, not base64 transport
  text.
- Kitty root image storage increments image and manager storage by decoded byte size;
  extra frames are bounded by disk-cache/load data size.
- Ghostty stores decoded `Image.data` and quota accounts `img.data.len`.
- Howl VT now has decoded image/frame payloads as model truth, but decoded quota still
  fails instead of evicting safe images.
- Howl legacy/base64 bytes remain public ABI compatibility and must stay bounded as a
  separate compatibility limit.

## Required Work

- Edit only `howl-vt/src/kitty/graphics.zig` and
  `howl-vt/src/test/terminal_graphics.zig` unless a stop condition is hit.
- No public ABI changes.
- No render or host changes.
- No image identity redesign.
- Count decoded protocol storage from:
  - image decoded payloads.
  - frame decoded payloads.
  - current decoded override payloads.
  - in-flight decoded upload bytes.
- `ensureDecodedPayloadStore` must evict safe unplaced images before returning
  `ConsequenceLimit`.
- Preserve images with physical placements.
- Preserve images with virtual placements.
- Replacement of the same image id must count decoded bytes freed by the old image, old
  frames, and current decoded override.
- Eviction must remove image data, frames, and current override payloads.
- Keep retained/base64 quota as compatibility-only bound.
- Add assertions around decoded/retained accounting after store/evict paths where useful.

## Tests Required
