# Current Slice: Truncate Direct Raw Oversize Slack

Owner: workspace root.

Sprint scope: graphics.

Promoted from `graphics-machinery-scratchpad.md` after direct raw oversize research.

## Goal

Match Kitty behavior for uncompressed direct raw graphics payloads whose decoded byte length is within Kitty's explicit `expected_raw_len + 10` slack.

## Target Files

- `howl-vt/src/kitty/graphics.zig`
- `howl-vt/src/test/terminal_graphics.zig`

## Required Behavior

- For uncompressed direct raw uploads (`t=d`, `c` omitted, `f=24` or `f=32`), decoded length exactly equal to expected raw length keeps existing behavior.
- Decoded length greater than expected raw length and no more than `expected_raw_len + 10` succeeds.
- Accepted oversize direct raw payloads retain/publish only the first `expected_raw_len` decoded bytes, re-encoded as base64.
- Decoded length less than expected raw length keeps existing invalid raw failure behavior.
- Decoded length greater than `expected_raw_len + 10` is rejected without storing, using the existing invalid raw failure path for this slice.
- Completed chunked direct raw uploads use the same final validation/truncation behavior.

## Hard Constraints

- Do not change ABI, render, host, parser, terminal, FFI, or build files.
- Do not decode APC payloads in the parser or change parser payload ownership.
- Do not change PNG, zlib/compressed raw, indirect media, query, upload chunk lifecycle, parser validation, or quiet response handling.
- Do not add broad Kitty `EFBIG` taxonomy; larger-than-slack direct raw keeps the existing invalid raw failure path.
- Do not change EBADPNG behavior, PNG mode behavior, storage quota, animation, frame, delete/reset, composition, or generated placeholder behavior.
- Do not replace retained base64 model truth in this slice.
- Do not special-case yazi/panes.
- Keep the smallest correct diff.

## Required Tests

- Single direct RGB raw upload with decoded length `expected + 10` stores only the expected bytes.
- Single direct RGBA raw upload with decoded length `expected + 10` stores only the expected bytes.
- Single direct raw upload with decoded length `expected + 11` rejects and stores no image.
- Chunked direct RGB raw upload with final decoded length `expected + 10` stores only the expected bytes.
- Chunked direct raw upload with final decoded length `expected + 11` rejects and stores no image.
- Existing exact, invalid-base64, and undersize direct raw tests continue to pass.

## Verification Required

- `zig build test` in `howl-vt`
- `zig build test:regression:build` in `howl-vt`
- `git diff --check` at workspace root

Stop condition:

- If correct behavior requires parser payload ownership changes, broad error taxonomy changes, host/runtime changes, render changes, ABI changes, or decoded/cache storage rewrites, stop and report the exact dependency instead of widening the slice.
