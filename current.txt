# Current Slice: VT Graphics Parser Validation

Owner: workspace root.

Sprint scope: graphics.

Promoted from `graphics-machinery-scratchpad.md` item 3 after placeholder assembly proof was recorded in root `f83947d`.

## Goal

Make Kitty graphics control-block parsing reject malformed syntax and invalid flag/integer domains before graphics state mutation, matching Kitty `parse_graphics_code` behavior for parser validation.

## Target Files

VT:

- `howl-vt/src/kitty/protocol.zig`
- `howl-vt/src/action/vocabulary.zig`
- `howl-vt/src/kitty/graphics.zig`
- `howl-vt/src/test/action_mapping.zig`
- `howl-vt/src/test/terminal_graphics.zig`

## Required Behavior

- Valid existing graphics commands continue parsing and handling unchanged.
- Unknown graphics control keys fail parsing and do not reach `State.handle`.
- Missing `=`, empty fields, trailing comma/incomplete field, malformed separators, invalid flag bytes, empty integer values, non-digit unsigned values, invalid signed values, and overlarge integer values fail parsing.
- Invalid parser input must not mutate graphics image/placement/upload state.
- Invalid parser input must not emit graphics protocol replies; Kitty parser logs and does not call `screen_handle_graphics_command`.
- `a`, `d`, `t`, and `o` flag domains match Kitty's generated parser.
- `q`, `m`, `C`, and `U` remain integer fields where nonzero maps to true for Howl's bool fields.

## Hard Constraints

- Do not edit render or host in this slice.
- Do not reinterpret placeholder protocol diacritics.
- Do not move base64 payload decoding into the parser in this slice; preserve existing payload ownership unless required for a syntax gate.
- Do not add renderer-side corrections.
- Do not make invalid parser input become an `EINVAL` graphics reply; it should fail before state handling.
- Keep the smallest correct diff.

- `zig build test` in `howl-vt`
- `zig build test:regression:build` in `howl-vt`
- `git diff --check` at workspace root

Stop condition:
