# Current Slice: Delete Host VT Viewport Lie

Owner: workspace root.

Purpose:

- Delete `howl-linux-host/src/terminal/vt/viewport.zig` as a false VT owner.
- Keep VT scrollback/display offset mutation in `terminal/vt/retained.zig`.
- Move host scrollbar/input/layout adaptation to a host terminal owner file.
- Follow Alacritty's split: terminal/grid owns display offset; event/display context only translates host input and rendering overlays.

## Source Facts

- Alacritty `alacritty_terminal/src/term/mod.rs` owns `Term::scroll_display`.
- Alacritty `alacritty_terminal/src/grid/mod.rs` owns `Grid::scroll_display` and `display_offset`.
- Alacritty app `alacritty/src/event.rs` translates input into `terminal.scroll_display(...)` and marks host dirty state.
- Howl `terminal/vt/retained.zig` already owns `scrollback_offset`, `setScrollbackOffset`, `followLiveBottom`, and clamping.
- Howl `terminal/vt/viewport.zig` imports window geometry, host input, scrollbar state, and SDL time, so it is not a VT owner.

## Non-Goals

- Do not move scrollback offset into host code.
- Do not change public C ABI.
- Do not change scrollbar behavior, mouse behavior, page-scroll behavior, layout geometry, passive hover wake behavior, focus behavior, or redraw policy.
- Do not rename unrelated `viewport` terminology in Alacritty references, render comments, or damage code.
- Do not introduce aliases, shims, or compatibility wrappers.

## Invariants

- Alternate screen still rejects host scrollback movement.
- Page scroll still moves by `max(visible_rows - 1, 1)` rows.
- Wheel fallback still moves 3 rows.
- Scrollbar mouse drag still clamps offset through VT retained state.
- Scrollbar invalidation still occurs only when focus/geometry/offset changes require it.
- Passive hover wake remains a host scrollbar concern, not VT state.
- No imports from `terminal/vt/` to `window/`, `input/`, or SDL for this adapter remain.
