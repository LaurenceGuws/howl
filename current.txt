## Required Product Shape

- Keep the realizer internal-only.
- Use shipped C ABI structs and macros through `ffi.zig`; do not duplicate ABI
  structs or constants.
- Accept `HOWL_RENDER_V0_RESOURCE_GLYPH_ATLAS_ALPHA` create only with
  `width_px = 1024`, `height_px = 1024`, and `format = HOWL_RENDER_V0_UPLOAD_ALPHA8`.
- Reject `HOWL_RENDER_V0_RESOURCE_GLYPH_ATLAS_COLOR` create, upload, and use.
- Accept alpha glyph atlas uploads only when the resource is live, unretired, the
  generation matches, the format is `UPLOAD_ALPHA8`, stride/count bounds are
  checked with overflow-safe arithmetic, and the upload rect fits the page.
- Realize `HOWL_RENDER_V0_COMMAND_DRAW_GLYPH_RUN` by drawing each glyph ref in
  source order from `atlas_resource`/`atlas_rect` to final `x_px/y_px`.
- For alpha glyphs, compute source alpha as `(color_rgba.a * alpha_byte) / 255`
  and blend with the same integer source-over semantics already used by the
  realizer for fills/sprites.
- Clip destination pixels to `frame.render_px`; clip source pixels by the same
  offset.
- Reject empty glyph runs, glyph span overflow, zero-alpha alpha glyph refs,
  missing/wrong-generation/retired atlas resources, atlas rects outside the page,
  zero-size atlas rects, unknown atlas kinds, and color glyph refs.
- Do not allocate heap memory inside realization.

## Required Invariants

- Render protocol lifetime remains explicit: create, update, use, retire, ack,
  reuse.
- Resource validation must finish before mutating caller-visible pixels for a
  rejected frame.
- All span counts, byte counts, pixel offsets, and `width * height * bytes_per_px`
  calculations must be checked for overflow before use.
- The realizer must not read past uploaded byte counts or span counts.
- The realizer must not silently draw missing glyphs.
- RGB/BGR/LCD/subpixel uploads remain unsupported.
- Full RGBA remains oracle/fallback only, not a glyph atlas color path.
