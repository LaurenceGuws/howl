# Current Slice: Render Decoded Graphics Commit ABI

Owner: howl-render.

Sprint scope: graphics.

## Goal

Add a parallel render C ABI commit-slot path for VT-decoded graphics bytes without
breaking the existing base64/protocol render ABI.

VT already exposes decoded graphics query/copy ABI. Render and the Linux host still use
the old base64/protocol payload path. This slice makes render capable of accepting
decoded RGB/RGBA image bytes through a new commit-slot ABI. The Linux host switchover is
a later slice.

## Source Findings

- Existing render C ABI commit and VT-surface structs carry `HowlVtGraphicsImage` plus a
  single `graphics_payload_bytes` blob; those bytes are old VT protocol/base64 payloads.
- Existing render graphics preparation decodes RGB/RGBA from base64 payload bytes.
- VT decoded publication now exposes decoded graphics bytes in parallel and preserves the
  old VT base64 ABI.
- Linux host cannot switch to VT decoded bytes before render gains decoded input; old
  render ABI would interpret decoded RGB/RGBA as base64.

## Required Work

- Do not mutate existing render C ABI structs or functions.
- Add a parallel decoded graphics commit-slot ABI:
  - decoded image span using `HowlVtGraphicsDecodedImage`.
  - decoded commit struct mirroring `HowlRenderPublishSlotCommit`.
  - `howl_render_surface_text_commit_publish_decoded_graphics_slot`.
- Add matching Zig FFI extern structs and compile-time layout assertions.
- Extend render internal publication state with explicit graphics payload kind:
  - legacy base64/protocol.
  - decoded pixels.
- Preserve old base64/protocol validation and decoding behavior.
- Decoded path accepts only:
  - `format == 24`: RGB bytes, `width * height * 3`.
  - `format == 32`: RGBA bytes, `width * height * 4`.
- PNG is not decoded in render on the decoded path; VT decoded publication already reports
  PNG as RGBA format `32`.
- Include payload kind in the graphics raster cache key so old base64 payload bytes and
  decoded pixel bytes cannot share a key accidentally.

## Tests Required

- Existing old render publish/commit ABI still accepts base64 payloads.
- New decoded commit ABI prepares a 1x1 RGB image from raw decoded bytes.
- New decoded commit ABI prepares a 1x1 RGBA image from raw decoded bytes.
- Decoded commit rejects truncated/trailing decoded payload bytes.
- Decoded commit rejects unsupported decoded formats.
- Cache key distinguishes base64/protocol payload kind from decoded payload kind.
- Prepared graphics image refs remain exposed after decoded prepare.

## Out Of Scope

- No Linux host switchover.
- No VT changes.
- No removal or deprecation of old render base64/protocol ABI.
- No quota/eviction redesign.
- No renderer-side Kitty protocol interpretation.
- No direct decoded `publish_vt_source` unless required to keep the commit-slot ABI
  implementation coherent.
