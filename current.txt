Owner: workspace root.

## Required Shape

- Follow the exact header order from `c-abi-header-grammar.md`:
  1. Include guard.
  2. C includes.
  3. `extern "C"` block.
  4. Opaque handles.
  5. Limits/macros.
  6. Status/result enums.
  7. Product enums.
  8. Structs.
  9. Functions grouped by owner handle and operation order.
- Use one opaque handle declaration style:
  - `typedef struct Howl<Package><Owner>Opaque *Howl<Package><Owner>Handle;`
- Wrap all function prototypes to stay under 100 columns.
- Remove ornamental banners, numbered sections, table-of-contents comments, and one-off prose comments
  that compensate for bad order.
- Keep only comments that explain ABI consequence, lifetime, ownership, units, or value permanence.

## Non-Goals

- No C symbol renames.
- No enum numeric changes.
- No struct field additions, removals, reorders, or type changes.
- No behavior changes.
- No Zig source edits.
- No compatibility typedefs, compatibility enum values, or macro aliases.
- No generation tooling.
- Do not normalize `libhowl_*.zig` roots in this slice.

## Invariants

- Declaration dependencies still compile as C and C++ headers through current Zig translate-C tests.
- PTY remains compact and direct.
- VT loses numbered banners and starts reading as a product header, not a hand table of contents.
- Render loses one-off section prose and long prototype lines.
- All public function prototypes are at most 100 columns.
- ABI layout tests still pass.
