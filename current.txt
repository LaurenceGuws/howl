# Current Slice: Direct Raw EFBIG Taxonomy

Owner: workspace root.

Sprint scope: graphics.

## Goal

Match Kitty's `EFBIG:Too much data` failure taxonomy for direct uncompressed raw
graphics payloads whose decoded length exceeds Kitty's accepted `expected_raw_len + 10`
slack.

## Required Behavior

- Keep direct uncompressed raw decoded payloads up to `expected_raw_len + 10` accepted
  and truncated to expected image truth.
- Reject decoded direct raw payloads larger than `expected_raw_len + 10` with graphics
  reply `EFBIG:Too much data`.
- Apply the same `EFBIG` taxonomy to completed direct chunked raw uploads.
- Preserve `q=1` failure emission and `q=2` failure suppression.
- Preserve existing `EINVAL:invalid kitty graphics data` behavior for undersize raw,
  invalid base64, zero dimensions, and other non-oversize invalid raw data.
- Do not change PNG, zlib, indirect media, parser payload ownership, render, host, ABI,
  storage, placement, animation, delete/reset, or generated-placeholder behavior.

## Required Tests

- Single direct RGB raw upload with decoded length `expected + 11` replies
  `EFBIG:Too much data` and stores no image.
- Chunked direct RGB raw upload with final decoded length `expected + 11` replies
  `EFBIG:Too much data`, clears pending upload, and stores no image.
- Single direct raw `expected + 11,q=1` emits the same `EFBIG` failure reply.
- Single direct raw `expected + 11,q=2` emits no reply and stores no image.
- Existing `expected + 10` slack tests remain green.
- Existing undersize and invalid-base64 tests remain `EINVAL:invalid kitty graphics data`.
