# Current Slice: V0 Prepared Sprite Resource Bound

Owner: `howl-render` V0 prepared sprite resource emission and lifetime.

Purpose:

- Stop prepared V0 sprite cache exhaustion from permanently disabling the V0 sidecar.
- Bound renderer-owned persistent sprite resources before `HOWL_RENDER_V0_RESOURCES_MAX` pressure.
- Provide explicit transient sprite resource fallback/diagnostics instead of silent full-RGBA steady-state fallback.
- Keep full RGBA fallback/oracle unchanged.

## Required Shape

- Existing persistent sprite resources remain reusable.
- New sprite resources must not grow the persistent cache past a bounded budget.
- When a sprite cannot become persistent, emit same-frame create/upload/draw/retire if V0 frame limits allow it.
- If transient emission exceeds frame limits, preserve full RGBA fallback and report the exact bound.
- Do not invent host-owned eviction or backend ack in this slice.

## Required Tests

- Existing host tests pass.
- Protocol proof tests cover persistent cache reuse, bounded persistent growth, transient create/upload/draw/retire, and exact overflow status.
- Bounded `btop` smoke should not enter steady-state `v0_emit_status=5` / `no_sidecar_call_failed` fallback after persistent resource pressure.
