# Current Slice: Graphics Animation Drawn-Visibility Runtime Gate

Owner: howl-vt, howl-render, and howl-linux-host.

Sprint scope: graphics.

## Goal

Gate VT graphics animation runtime on render-confirmed drawn image refs instead of
animation state plus frame count alone.

## Required Behavior

- VT images have a stable nonzero image ref id for their lifetime.
- Render carries visible prepared image ref ids after viewport clipping and raster
  binding.
- Host reports prepared/rendered drawn image refs back to VT through the C ABI.
- VT `imageNeedsRuntime()` requires the image to be drawn by the last accepted render
  feedback.
- Unplaced, deleted-placement with empty drawn feedback, and virtual-only animations
  have no runtime obligation and do not advance.
- Do not approximate off-screen visibility in VT from placement counts.

## Reference Notes

- Kitty `grman_update_layers()` clears `Image.is_drawn`, skips virtual refs, skips
  off-screen refs, and sets drawn only after visible non-virtual render data exists.
- Kitty delete/scroll/ref mutations dirty layers; drawn truth converges through the
  render/layer update path.
- Ghostty has no direct animation-runtime match; Kitty graphics animation is
  unimplemented there.
