Owner: workspace root.

Source scratchpad:

- Promoted item: `Slice G: Placeholder/Ordinary Ordering Contract`

## Goal

Decide the correct ownership and ABI shape for ordering placeholder-backed graphics relative to ordinary graphics placements.

This is a research/design slice. Do not seed a coding worker until the ownership answer and smallest acceptable ABI/code slice are unambiguous.

## Current Baseline

- VT owns placeholder decoding, inheritance, virtual placement binding, and placeholder run publication.
- Render consumes VT-exported placeholder runs.
- Render now rejects missing virtual placement source/grid truth instead of inferring it.
- Render still locally merges placeholder-backed draw items with ordinary z=-1 placements in `surface_buffer.zig`.

## Question

Is render's current placeholder/ordinary merge order legitimate render draw policy, or stale semantic ownership that should move to VT/ABI as explicit compositing order truth?

## What To Research

- Kitty protocol ordering rules for Unicode-placeholder images, ordinary placements, negative z, same z, and same image id.
- Whether Kitty defines ordering between placeholder-derived images and ordinary placements when both are below text.
- Ghostty's exact ownership shape for placeholder render z/order and whether that maps to Howl's C ABI boundary.
- How Alacritty-style host/render separation affects whether ordering belongs in VT export or render sorting.
- TigerBeetle-grade proof requirements if Howl keeps render-local ordering versus moves it to ABI truth.
