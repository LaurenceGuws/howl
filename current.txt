# Current Slice: Reject Oversized Animation Frames

Owner: workspace root.

Sprint scope: graphics.

Promoted from `graphics-machinery-scratchpad.md` after animation frame dimension research.

## Goal

Match Kitty behavior by rejecting animation frame uploads whose loaded frame dimensions exceed the existing base image dimensions.

## Target Files

- `howl-vt/src/kitty/graphics.zig`
- `howl-vt/src/test/terminal_graphics.zig`

## Required Behavior

- For `a=f` frame uploads, compute the loaded/intrinsic frame dimensions before mutating frame state.
- If loaded frame width is greater than the base image width, reject with `EINVAL:Frame width {frame_width} larger than image width: {image_width}`.
- If loaded frame height is greater than the base image height, reject with `EINVAL:Frame height {frame_height} larger than image height: {image_height}`.
- Rejection stores no frame, preserves existing frame/image state, and follows existing quiet failure suppression.
- Valid frame uploads keep existing behavior.

## Hard Constraints

- Do not change ABI, render, host, parser, terminal, FFI, or build files.
- Do not implement broader root-frame edit parity, frame graph/ref semantics, cache/storage identity, or animation runtime changes.
- Do not change successful frame upload behavior, frame-number allocation, current-frame selection, frame gaps, or composition behavior.
- Do not change PNG decoder behavior, zlib/compressed raw, direct/indirect media normalization, query, delete/reset, parser validation, quiet semantics, or EBADPNG behavior.
- Do not replace retained base64 model truth in this slice.
- Do not special-case yazi/panes.
- Keep the smallest correct diff.

## Required Tests

- Width-oversized raw frame upload against a `1x1` base image replies with the Kitty `EINVAL` width message and stores no frame.
- Height-oversized raw frame upload against a `1x1` base image replies with the Kitty `EINVAL` height message and stores no frame.
- Existing-frame edit with oversized dimensions rejects and preserves the previous frame payload/metadata.
- `q=1` still emits the oversized-frame failure.
- `q=2` suppresses the oversized-frame failure and stores no frame.
- Existing valid frame upload tests continue to pass.

## Verification Required

- `zig build test` in `howl-vt`
- `zig build test:regression:build` in `howl-vt`
- `git diff --check` at workspace root

Stop condition:

- If correct behavior requires broader root-frame edit parity, frame graph/ref rewrites, parser changes, host/runtime changes, render changes, ABI changes, or decoded/cache storage rewrites, stop and report the exact dependency instead of widening the slice.
