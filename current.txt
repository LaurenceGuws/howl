# Current Slice: VT Graphics Decoded Publication ABI

Owner: howl-vt.

Sprint scope: graphics.

## Goal

Add an ABI-compatible decoded graphics publication path owned by VT, while preserving
the existing base64/protocol payload ABI exactly.

## Source Findings

- Kitty parser decodes graphics APC payload base64 before graphics manager dispatch.
- Kitty `LoadData` owns decoded bytes for direct, file/temp/shared-memory mapped input,
  zlib-inflated input, and PNG-decoded input before image/frame storage.
- Ghostty parser returns command-owned decoded `data`; loading images and completed
  images own decoded bytes and quota accounts `Image.data.len`.
- Howl's existing `HowlVtGraphicsImage.payload_len` and
  `howl_vt_terminal_copy_graphics_payload` are real product ABI and explicitly expose
  retained protocol/base64 bytes.
- Howl VT `Image.base64_payload`, `Frame.base64_payload`, and render-side base64 decode
  are stale internal/integration shape, but cannot be removed in this slice.

## Required Behavior

- Add parallel decoded graphics image query/copy C ABI in `howl-vt`.
- Preserve `HowlVtGraphicsImage` layout and `howl_vt_terminal_copy_graphics_payload`
  semantics exactly.
- VT owns decoded bytes; host only copies; render is not switched in this slice.
- Decoded publication exposes format, width, height, and byte length for decoded image
  bytes.
- PNG decoded publication exposes RGBA bytes with format `32`.
- Direct zlib and chunked zlib decoded publication exposes decompressed decoded bytes.
- Chunked direct decoded publication reflects concatenated decoded chunk bytes.
- Add explicit bounds/assertions for decoded retained bytes; do not silently double
  memory without a bound.

## Acceptance Tests

- Old base64 ABI unchanged for direct raw upload.
- Decoded ABI returns raw direct RGB/RGBA bytes.
- Decoded ABI returns decompressed zlib bytes.
- Decoded ABI returns RGBA bytes for PNG.
- Chunked direct decoded bytes equal concatenated decoded chunks.
- Invalid publication sequence and invalid image index reject through decoded APIs.

## Out Of Scope

- No render switchover.
- No host protocol decode.
- No quota/eviction redesign beyond explicit decoded-byte bound.
- No breaking C ABI changes.
- No removal of compatibility base64 publication.
- No frame graph redesign; stop if current-frame decoded publication requires it.
