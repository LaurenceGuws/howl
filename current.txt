# Current Slice: Placeholder Ordering Proof

Owner: workspace root.

Source scratchpad:

- Promoted item: `Slice G: Placeholder/Ordinary Ordering Contract`

## Decision

Keep placeholder/ordinary graphics ordering as render compositor policy for now. Do not add VT or render ABI fields in this slice.

Research result:

- Kitty defines image `z`, negative-z bands, and lower-image-id ordering for same `z`.
- Kitty says Unicode-placeholder images are not ordinary protocol placements.
- Kitty does not define a stable global order between placeholder-derived images and ordinary placements with the same image id.
- Ghostty maps Unicode-placeholder render instances to renderer-side `z = -1` and sorts in the renderer.
- Howl render already receives VT-resolved placeholder runs and virtual placement truth; it does not need more VT protocol inference to compose them as render draw items.

Therefore:

- VT owns placeholder decoding, run order, virtual placement binding, and geometry truth.
- render owns compositor bands and deterministic pixel draw order.
- placeholder-backed graphics are render-local below-text draw items equivalent to `z = -1`.
- same-image/same-z details are deterministic Howl render policy, not Kitty protocol truth.

## Current Weak Shape

Current render behavior is mostly right but under-proved and under-named:

- `surface_buffer.zig` merges placeholder-backed graphics with ordinary `z = -1` placements.
- Existing tests cover several same-image/placement/run cases.
- Missing proof should make the intended compositor matrix explicit, especially ordinary `z < -1`, different image ids at `z = -1`, and same image/placement tie behavior.

## Required Proofs

Add or sharpen `surface_buffer.zig` tests proving:

- ordinary below-text placement with `z < -1` draws before placeholder-backed `z = -1` graphics.
- ordinary `z = -1` placement with lower image id draws before a placeholder-backed higher image id.
- placeholder-backed lower image id draws before ordinary `z = -1` higher image id.
- same image id and same placement id uses deterministic render-local tie behavior between placeholder `run_order` and ordinary `placement_ordinal`.
- existing placeholder-run ordering by placement id and exported run order remains intact.

Tests should assert final pixels, not only sort keys.
