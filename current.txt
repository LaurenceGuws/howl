# Current Slice: Placeholder Combining Marks And Generated Row Geometry

Owner: workspace root.

Sprint scope: graphics.

## Goal

Keep Kitty Unicode placeholder diacritics attached to their `U+10EEEE` lead cell so yazi placeholder rows materialize as contiguous generated placements, then publish those generated rows with exact pixel bounds.

## Target Files

- `howl-vt/src/screen/write.zig`
- `howl-vt/src/kitty/graphics.zig`
- `howl-vt/src/test/screen_state_behavior.zig`
- `howl-vt/src/test/terminal_graphics.zig`

## Required Behavior

- Treat Kitty/yazi row-column diacritics outside the basic `U+0300...U+036F` block as trailing combining codepoints.
- Preserve existing behavior for basic combining marks, zero-width joiners, variation selectors, and non-combining printable codepoints.
- Do not special-case yazi or graphics commands in screen writing.
- Generated placeholder placements must publish exact partial-row destination pixel bounds instead of recomputing them from rounded source aspect ratio.
- Do not change ABI, render, host, parser control handling, upload/storage, or presentation behavior.

## Required Tests

- A placeholder lead cell followed by `U+0483` keeps that mark in the lead cell's combining buffer and advances the cursor only once.
- A generated placeholder placement whose rounded source aspect would overestimate destination height still publishes the exact clipped destination height.
- Existing screen and graphics tests continue to pass.

- `zig build test` in `howl-vt`
- `zig build test:regression:build` in `howl-vt`
- root `git diff --check`

Stop condition:
