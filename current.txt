Owner: workspace root.

Sprint scope: graphics.

Promoted from `graphics-machinery-scratchpad.md`.

## Goal

Implement VT-owned generated cell placements for Unicode placeholders, matching Kitty's screen-owned cell-image materialization model.

## Required Acceptance Tests

- Placeholder cells create generated z `-1` placements in VT, not render-only protocol geometry.
- Rewriting or clearing a placeholder row removes stale generated placements.
- Updating a virtual placement redraws or republishes existing placeholder rows.
- Generated placements preserve image id, placement id, source fragment row/column, run width, screen row/column, and a stable link to the virtual placement equivalent to Kitty's virtual ref linkage.
- Existing placeholder run assembly tests remain valid.

## Hard Constraints

- Keep Kitty protocol consequences in `howl-vt`.
- Do not add new render-side placeholder interpretation.
- Do not reinterpret protocol diacritics as 1-based.
- Do not special-case yazi or pane positions.
- Do not edit `howl-render` in this slice unless a reviewed blocker proves the VT ABI shape is impossible.
- Prefer the smallest ABI addition that lets hosts/render consume generated placements as normal placement truth.

## Verification Required

- `zig build test` in `howl-vt`
- `zig build test:regression:build` in `howl-vt`
- If ABI changes require it, run `zig build test` in `howl-render` and `zig build test:unit` in `howl-linux-host`.
- `git diff --check` at workspace root

Stop condition:

- If a correct ABI shape cannot be proven within VT boundary rules, stop and report the exact blocker. Do not invent a render shortcut.

## Blocker Found

The first worker attempt proved this slice is not safely VT-only.

- Publishing generated placeholder placements through the existing normal placement stream while `placeholder_run_count` remains exported would make current render consume both paths and potentially double-draw placeholder images.
- Adding generated-placeholder metadata to `HowlVtGraphicsPlacement` is a public ABI change and requires coordinated `howl-render`/host ABI updates, not a VT-only patch.

Next required step:

- Start a coordinated scratchpad/current slice for VT generated cell refs plus render placeholder-path replacement, or do a smaller research round to define the exact ABI transition that avoids double drawing.
