# Current Slice: Host-Owned Present Acknowledgement

Owner: workspace root.

Source scratchpad:

- `render-surface-hardening-scratchpad.md`
- Promoted item: `Slice E: Present/Retire Final Contract`

## Decision

Move presentation acknowledgement identity out of `howl-render` and into the host.

Research result:

- Ghostty does not put terminal snapshot presentation acknowledgement in terminal/render queue state.
- Alacritty owns presentation, pacing, redraw, and swap completion in the host/window/event loop.
- TigerBeetle-grade proof wants retained render base and host presentation acknowledgement as separate state machines.

Therefore:

- render owns submitted-frame retained-base truth
- host owns presentation-in-flight and VT source acknowledgement truth

## Current Bad Shape

Current render state conflates two concepts:

- `submitted_frame`: legitimate render-retained base identity
- `presented_frame`: host/window presentation lifecycle identity living in render

Current bad paths:

- `howl-render/src/frame/queue.zig` sets both `submitted_frame` and `presented_frame` in `acceptSubmitted()`.
- `howl-render/src/frame/queue.zig` exposes `retirePresented()` and `present_pending` as render-owned public truth.
- `howl-render/src/frame/surface_text_ffi.zig` exposes `retirePresented()` through the C ABI.
- `howl-linux-host/src/terminal/render/retained.zig` asks render which snapshot to retire after the host presents.
- `howl-linux-host/src/terminal/terminal_panel.zig` blocks submit on render-owned `present_pending` even though the host owns the actual present cadence.

## Required Render Contract

In `howl-render`:

- Remove `TerminalSurface.presented_frame`.
- `acceptSubmitted()` updates only `submitted_frame`.
- Remove `TerminalSurface.retirePresented()` and `Flow.retirePresented()`.
- Remove render-owned `present_pending` from `PendingState` and FFI pending output.
- Remove `FfiPresentedRetire` if unused after ABI cleanup.
- Remove `surface_text_ffi.retirePresented()`.
- Remove `howl_render_surface_text_retire_presented` export.
- Remove `HowlRenderPresentedRetire` and `howl_render_surface_text_retire_presented()` from `include/howl_render.h`.
- Keep render submitted-frame validation and retained-base behavior unchanged.

ABI note:

- This is an intentional ABI contract sharpening. Do not leave dead `present_pending` or retire-present symbols as compatibility ghosts.

## Required Host Contract

In `howl-linux-host`:

- Add host-owned `present_in_flight: ?u64` to `render_retained.State` or the nearest true host presentation owner.
- `WorkState.present_pending` may remain as host-owned state, but it must no longer come from render C ABI.
- `State.pending()` should combine render source/prepare/submit pending with host `present_in_flight != null`.
- On successful submit/rendered result, host records exactly the submitted snapshot sequence as `present_in_flight`.
- Use the prepared/upload info snapshot sequence already available during submit; do not ask render later.
- Host must not start another submit while `present_in_flight != null`.
- After `app.window.present()`, `TerminalPanel.finishPresent()` uses the host-owned pending snapshot sequence and calls `vt_surface.ackPublishedSourceLocked()` with exactly that sequence.
- `finishPresent()` must clear `present_in_flight` exactly once.
- Chrome-only present with no terminal present in flight must not ack VT snapshot `0`.

## Implementation Guidance

Preferred host shape:

- Add methods on `render_retained.State`:
  - `beginPresent(snapshot_seq: u64) void`
  - `finishPresent() ?u64`
  - `presentPending() bool` if useful
- `beginPresent()` asserts `snapshot_seq != 0` and no existing present in flight.
- `finishPresent()` returns the pending snapshot and clears it, or returns null when no terminal present is pending.
- `TerminalPanel.submitPrepared()` calls `beginPresent(upload.info.snapshot_seq)` only after `submit()` returns `.rendered`.
- `TerminalPanel.finishPresent()` acks VT only when `finishPresent()` returns a snapshot.

Render pending state:

- keep `source_pending`, `prepare_pending`, `submit_pending`, and `bootstrap_surface`
- remove render-owned `present_pending` from the C ABI
- preserve host `WorkState.present_pending` if it is now host-owned

## Required Proofs

Render proofs:

- submitted-frame retained-base tests still pass after removing `presented_frame`.
- `pendingState()` no longer exposes render-owned present pending.
- ABI size/header tests updated for removed pending field and removed retire type/function.
- no `retirePresented` symbol remains in render source/header/export.

Host proofs:

- successful render submit records `present_in_flight` with the submitted snapshot sequence.
- failed/stale/idle/needs-prepare submit does not create `present_in_flight`.
- render action blocks submit while host `present_in_flight != null`.
- `finishPresent()` with a pending snapshot acks exactly once and clears it.
- second `finishPresent()` without a new terminal present does not ack snapshot `0`.
- chrome-only present without terminal present pending does not ack VT.
- after finish-present clears pending state, next submit is allowed.

## Rejection Gates

Reject the worker diff if any of these happen:

- render still stores `presented_frame`
- render still exposes `retirePresented()` or `howl_render_surface_text_retire_presented`
- render C ABI still exposes `present_pending` as render-owned truth
- `acceptSubmitted()` still means “presented”
- host acknowledges VT by asking render which snapshot to retire
- host can ack snapshot `0`
- failed/stale/idle/needs-prepare submit creates host present-in-flight state
- submit can proceed while host present-in-flight is set
- tests cover only happy path
- ABI/header changes are not reflected in Zig FFI types/tests/exports
