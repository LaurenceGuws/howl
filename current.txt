## Goal

Make the prepared-buffer export and submit execution seam agree on upload truth.

This slice does not rename the shipped ABI field. It makes the current shipped names provable by enforcing pair contracts at the owner boundary.

## Current Bad Shape

Current code has two meanings around `uploads_committed`:

- `prepared_surface_owner.Owner.buffer()` returns `uploads_required` through the shipped `FfiPreparedSurfaceBuffer.uploads_committed` field.
- `surface_text.SurfaceText.submitSurface()` records `execution.uploads_committed` as host-realized work in `RenderSurfaceFeedback` and metrics.
- There is no owner check that the host-reported realized uploads match the prepared owner’s required uploads.
- There is no owner check that the host surface dimensions match the prepared render dimensions.

Current relevant paths:

- `prepared_surface_owner.Owner.buffer()` exports the required upload count.
- `surface_text_ffi.executionInputIn()` translates host execution input.
- `prepared_surface_owner.Owner.submit()` and `submitOwned()` call `session.submitSurface()`.
- `surface_text.SurfaceText.submitSurface()` marks raster outputs rendered and reports `execution.uploads_committed`.
- `submit_feedback.renderMetrics()` stores `uploads_committed` in `metrics.uploads`.

## Reference-Derived Rule

- Ghostty-style owner seams do not let C-facing values silently change meaning after crossing the boundary.
- Alacritty-style rendering keeps host realization distinct from prepared render content.
- TigerBeetle requires pair assertions: the producer publishes required work, and the consumer reports realized work; the seam must prove they agree or reject the transition.

## Required Contract

Prepared phase:

- `Owner.buffer().uploads_committed` continues to export the prepared owner’s `uploads_required` because the ABI field name is shipped.
- The code comment must remain explicit that this value is required uploads at prepare-buffer export time.

Submit phase:

- `execution.uploads_committed` is host-realized uploads.
- A submit may proceed only when `execution.uploads_committed == owner.uploads_required`.
- A submit may proceed only when `execution.surface.width == owner.render_px.width`.
- A submit may proceed only when `execution.surface.height == owner.render_px.height`.
- Rejection should happen in `prepared_surface_owner.Owner` before `session.submitSurface()` mutates atlas/render state.

Feedback phase:

- `RenderSurfaceFeedback.uploads_committed` and `metrics.uploads` remain host-realized upload counts.
- Because submit rejects mismatches, these values are now proven equal to the prepared owner’s required upload count for accepted submits.

## Implementation Guidance

Prefer a small owner-local check in `prepared_surface_owner.Owner`, before `performSubmit()` calls `session_owner.session.submitSurface()`.

Acceptable shape:

- Add a tiny helper such as `executionMatchesPrepared()` or `validateExecution()` on `Owner`.
- Use direct checks, not dense compound conditions.
- Return `.failed` from `submit()` / `submitOwned()` when dimensions or uploads do not match.
- Keep the C ABI unchanged.

Do not put this policy in `surface_text_ffi.executionInputIn()` unless it is only translating values. FFI translates contracts; the prepared owner owns the prepared dimensions and required upload count.

## Required Proofs

Add or update tests.

Required ABI proofs:

- prepared buffer export reports required upload count.
- submit with matching surface dimensions and upload count succeeds.
- submit with wrong `uploads_committed` fails.
- submit with wrong surface width fails.
- submit with wrong surface height fails.
- failed submit from upload/dimension mismatch does not consume the prepared handle; a later matching submit can still succeed.
- accepted submit feedback metrics report uploads equal to the realized count.

If generating non-zero uploads through the full ABI is too heavy, use the smallest owner-local test in `prepared_surface_owner.zig` to prove non-zero `uploads_required` mismatch/match behavior, and keep ABI tests for dimension mismatch and zero-upload success. Do not skip non-zero upload proof entirely.
