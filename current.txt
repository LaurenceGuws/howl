## Required Content

The grammar document must define one exact header order:

1. Include guard.
2. C includes.
3. `extern "C"` block.
4. Opaque handles.
5. Limits/macros.
6. Status/result enums.
7. Product enums.
8. Structs.
9. Functions grouped by owner handle and operation order.

The document must also define:

- One handle declaration style.
- One status/result enum style.
- One macro/limit style.
- One function prototype wrapping style under 100 columns.
- One comment rule: comments explain ABI consequence/lifetime only; ordering does navigation.
- Header banners are banned unless generated consistently by future tooling.
- No compatibility aliases or old-name typedefs.
- No Zig-shaped host shortcut or Ghostty-style broad Zig module lane.
- How to pair header declarations with Zig ABI layout assertions and FFI translators.
- Review checklist for later header implementation.
- Grep gates for later implementation.

## Invariants

- The document is exact enough that a later worker cannot invent ordering.
- The grammar supports one small intuitive C lane for Howl.
- The grammar does not create new buckets such as `manager`, `controller`, `runtime`, `pipeline`,
  `queue`, `types`, `api`, or `abi` owners.
- The grammar is compatible with PTY, VT, and render public headers.
