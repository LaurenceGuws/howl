# Current Slice: Split Render Source ABI From VT Types

Owner: workspace root.

Purpose:

- Remove `howl-render` public C ABI dependency on `howl-vt` public C structs.
- Keep VT as owner of terminal state truth.
- Keep render as owner of render source structs, retained prepare state, shaping, prepared surfaces, and submit contracts.
- Prepare the ground for a later Zig 0.16 build-system translate-C migration in `howl-linux-host` without combined C buckets.

## Source Research

Use `render-vt-abi-decoupling-scratchpad.md` as the sprint scratchpad.

Reference verdict:

- Ghostty supports VT-owned render-state adaptation, not renderer backend ABI owning VT cell truth.
- Alacritty adapts terminal `Cell` into display `RenderableCell`; renderer consumes adapted renderable content.
- Kitty privately couples renderer to `Screen *`, but public/renderer-facing draw data is packed draw state, not terminal structs as public ABI.

## Source Changes

Edit only:

- `howl-render/include/howl_render.h`
- `howl-render/src/vt_surface.zig`
- `howl-render/src/source/vt.zig`
- `howl-render/src/source/slot.zig` only if needed for render-owned names/layouts
- `howl-render/src/test/*` only for required test updates
- `howl-linux-host/src/terminal/vt/surface.zig` for host VT-to-render source conversion
- `howl-linux-host/src/terminal/vt/retained.zig` only if needed for retained VT scratch storage used by the conversion

Required shape:

- Remove `#include "howl_vt.h"` from `howl-render/include/howl_render.h`.
- Add render-owned public ABI structs for the data render consumes:
  - `HowlRenderSourceRgb`
  - `HowlRenderSourceColor`
  - `HowlRenderSourceCellFlags`
  - `HowlRenderSourceCellAttrs`
  - `HowlRenderSourceCell`
  - `HowlRenderSourceColors`
  - `HowlRenderSourceSelectionPos`
  - `HowlRenderSourceSelection`
  - `HowlRenderSourceCursor`
- Replace render ABI payload fields that currently use `HowlVt*` with `HowlRenderSource*`.
- Keep render publication function names stable for this slice unless renaming is necessary for correctness.
- Remove layout assertions against `c.HowlVt*` in `howl-render/src/vt_surface.zig`.
- Add layout assertions between `HowlRenderSource*` ABI structs and render-owned `source_vt` / `source_cell` structs.
- Host VT publication must explicitly convert VT ABI values into render source ABI values before committing to render.
- Host VT publication must not allocate per publish; if VT cells need temporary storage before conversion, store it in retained VT state with explicit capacity and deinit ownership.

## Non-Goals

- Do not migrate `howl-linux-host/src/terminal/c.zig` in this slice.
- Do not change VT public ABI structs in `howl-vt/include/howl_vt.h`.
- Do not introduce combined translate-C modules as a workaround.
- Do not add compatibility aliases or shims.
- Do not change render prepared surface semantics, text shaping behavior, dirty semantics, or submit behavior.

## Invariants

- VT remains the terminal state truth owner.
- Render public header has no dependency on `howl_vt.h`.
- Render source structs are render-owned C ABI product structs.
- Cell count remains `cols * rows` with existing bounds validation.
- Dirty row/column metadata validation remains unchanged or stronger.
- Cursor, colors, and selection are copied/adapted into render-owned source structs without changing meaning.
- No per-publish heap allocation in VT visible-surface acquisition or conversion.
- Existing host behavior remains equivalent.
