# Current Slice: Linux Host Decoded Graphics Bridge

Owner: howl-linux-host.

Sprint scope: graphics.

## Goal

Switch the Linux host graphics path to copy decoded graphics bytes from VT and publish
them through render's decoded graphics commit ABI.

Dependency state:

- `howl-vt` exposes decoded graphics query/copy ABI and preserves old base64 ABI.
- `howl-render` exposes decoded graphics commit-slot ABI and preserves old base64 ABI.

## Required Work

- Use `howl_vt_terminal_query_graphics_decoded_image` for host graphics image metadata.
- Use `howl_vt_terminal_copy_graphics_decoded_payload` for host graphics payload bytes.
- Publish retained render slots through
  `howl_render_surface_text_commit_publish_decoded_graphics_slot`.
- Keep host ownership as transient ABI copies only; do not decode Kitty protocol in host.
- Preserve old host behavior around publication sequence, visible metadata, placements,
  virtual placements, payload aggregation, prepared refs, and drawn feedback.
- Do not remove old VT/render ABI wrappers; they remain compatibility paths.

## Tests Required

- Existing Linux host kitty graphics replay build/integration tests still pass.
- Existing render drawn-ref feedback path still reports prepared decoded image refs.
- If host has unit coverage for retained graphics acquisition, update it to prove decoded
  image metadata and decoded payload copies are used.

## Out Of Scope

- No VT changes.
- No render changes.
- No old ABI removal or deprecation.
- No host-side protocol decode or base64 re-encode.
- No render cache/quota redesign.

## Stop Conditions

- Stop if host must decode or re-encode graphics payload bytes.
- Stop if render decoded ABI is insufficient and would require mutating old render ABI.
- Stop if VT decoded ABI is insufficient and would require mutating old VT ABI.
