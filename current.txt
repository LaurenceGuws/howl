## Required Product Shape

- Add an internal `emitPrepared`-style API in `protocol_v0/emit.zig`.
- Input is a real `PreparedSurface` and any session/cache access needed to match
  the current oracle; output remains emitter-owned internal V0 storage.
- Use the current prepared scene pass order exactly: clear, background,
  decoration, sprites, cursor.
- For sprites, match `prepared_buffer.compose()` lookup order and pixel semantics:
  current `raster_plan.outputs` first, then session atlas cache if needed.
- Upload sprite visual-resource bytes starting at resource-local `(0, 0)`.
- Offset emitted sprite destination rect by visual bounds exactly as the oracle does.
- Emit sprite create/upload/use/retire in the documented command-boundary domain.
- Fail closed without mutating a prior accepted emitted frame.
- Do not attach V0 storage to prepared handles in this slice.

## Required Invariants

- Every emitted frame must realize through `protocol_v0.realize()` and compare to
  `prepared_buffer.compose()` byte-for-byte in tests.
- All V0 span and upload byte limits are checked before writing.
- All sprite byte copies use checked bounds against raster width, height, stride,
  color mode, visual bounds, and source byte length.
- Missing sprite rasters reject instead of producing dangling resources.
- Published frame spans and upload byte pointers point into emitter-owned storage.
- Full RGBA remains oracle/fallback only.
