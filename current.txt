# Current Slice: VT Live Stream Direct Dispatch

Active research:

- `research/cache-2026-06-02-vt-direct-stream-readiness.md`

Reviewer acceptance:

- This slice is ready and narrow: remove the live `ParsedEvents` queue from `stream_terminal.zig` and keep `parser/events.zig` as parser/materialization vocabulary only.
- Preserve observable VT behavior and avoid ABI changes.

## Problem

`stream_terminal.State` still owns queued `ParsedEvents` and drains them through `route.apply`. Replace that live queue with direct parser-action dispatch, while preserving DCS payload reconstruction, charset state handling, and APC/PM overflow behavior.

## Allowed Files

- Edit: `howl-vt/src/stream_terminal.zig`

- Edit: `howl-vt/src/test/terminal_surface.zig`

## Required Shape

- `stream_terminal.State` owns `parser` plus direct-live control state, not a queued `ParsedEvents` store.
- Live byte handling maps parser actions directly to `route.apply`.
- `SO`/`SI` update terminal GL state directly.
- ESC charset designation updates terminal G0/G1 directly.
- DCS hooks/puts/unhook rebuild the same body/payload view that queued events used to expose.
- APC/PM overlong feeds are still bounded and fail with the existing stream error surface.

## Required Tests

- Keep existing VT unit and ABI tests green.
- Add or keep coverage for:
  - charset designation and GL shift across feed slices
  - DCS retained payload kind/body/payload across slices
  - overlong APC recovery
  - overlong PM recovery
