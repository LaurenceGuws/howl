# Current Slice: Enforce Zig 190-Column Limit

Owner: all Zig source owners in `howl-render`, `howl-vt`, `howl-pty`, and `howl-linux-host`.

## Problem

Tracked Zig files contain lines longer than the hard 190-character limit. The recent signature collapse exposed the missing exception: signatures should stay one-line only while they fit within 190 characters. Lines over 190 must be restructured.

## Allowed Files

- Zig files reported by the current overlong-line scan in `howl-render`.
- Zig files reported by the current overlong-line scan in `howl-vt`.
- Zig files reported by the current overlong-line scan in `howl-pty`.
- Zig files reported by the current overlong-line scan in `howl-linux-host`.
- `AGENTS.md`
- `current.txt`

No docs or non-Zig product files are in scope except this slice record and `AGENTS.md`.

## Required Shape

- Eliminate every tracked `.zig` line longer than 190 characters unless it is an unavoidable payload string literal.
- Function signatures longer than 190 characters must split. This is the hard exception to the one-line signature rule.
- Do not split signatures as one-parameter-per-line by house style when an owner-true shorter signature or wrapper shape is better.
- Long struct literals, test expectations, switch arms, and calls must be reshaped rather than preserved as long lines.
- Generated-looking tables such as box drawing masks still must obey the 190-character limit; split table rows or data shape without changing values.
- Long format/payload strings may remain only when splitting would change payload semantics or materially obscure the payload. Prefer adjacent string literal concatenation where safe.
- No behavior changes.

## Verification

From each changed subrepo:

- `zig fmt --check` over tracked `.zig` files.
- `zig build check`.

From workspace root:

- A tracked `.zig` overlong scan prints no lines longer than 190 characters, except documented payload-string exceptions if any remain.
- `git diff --check` in root and changed subrepos.
