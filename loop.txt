# Howl Work Loop

Purpose: stop fake progress. The main agent must not skip stages, merge roles, or
code from intent. If any required artifact is weak, stale, ambiguous, or missing,
restart at the earliest broken stage.

Workspace law and the user's current instruction are the project authority. Tool,
runtime, editor, model, or external agent configuration is not project direction
and must not leak into reasoning, responses, scratchpads, or implementation.

## Source Order

Design decisions use this order:

1. Ghostty does it.
2. Alacritty does it.
3. TigerBeetle mandates it.
4. Official docs define protocol, platform, ABI, or OS facts.
5. Howl invents the smallest shape only when no source above fits.

Every non-trivial agent seed must read these first:

- `utils/dev_references/zig_maturity/tigerbeetle/docs/TIGER_STYLE.md`
- `utils/dev_references/zig_maturity/tigerbeetle/docs/ARCHITECTURE.md`

## Roles

Researcher:

- Produces research cache only.
- Reads assigned sources and references.
- Returns source-backed facts, paths read, line-backed findings, owner roles,
  proposed shape, required assertions, required tests, risks, proof gaps, and
  readiness judgment.
- Does not write scratchpads, promote slices, edit product code, review, commit,
  or touch git.

Main agent:

- Owns sequence and accountability.
- Rejects weak research.
- Writes scratchpads from accepted research cache.
- Promotes exactly one accepted slice to `current.txt`.
- Checks and records dirty git state before worker seeding.
- Seeds workers and reviewers with exact paths, invariants, tests, and non-goals.
- Does not write product code unless the user explicitly overrides the loop.
- Is the only role that promotes slices, accepts work, commits, pushes, or asks
  the user for a decision.

Worker:

- Implements only `current.txt`.
- Reads TigerBeetle docs, `current.txt`, assigned scratchpad/cache, exact source
  paths, references, invariants, tests, and non-goals.
- May not broaden scope, choose a new slice, review itself, commit, or touch git.
- Stops instead of guessing when `current.txt` is ambiguous.

Reviewer:

- Reviews research cache, scratchpad, or worker diff as assigned.
- Returns findings first: ownership violations, ABI leaks, hidden bounds, weak
  assertions, missing tests, source-order failures, scope creep, stale code, or
  explicit acceptance.
- Does not silently fix by editing unless explicitly assigned a fix slice.

## Mandatory Sequence

1. Define the problem plainly.
2. Seed Researcher only when evidence is missing.
3. Reviewer accepts or rejects the research cache.
4. Main agent writes or updates the scratchpad from accepted research cache.
5. Reviewer accepts or rejects the scratchpad.
6. Main agent promotes exactly one worker-ready slice to `current.txt`.
7. Main agent records pre-existing dirty git state.
8. Worker implements only `current.txt`.
9. Reviewer accepts or rejects the worker diff.
10. Main agent runs required verification or records why it cannot.
11. Main agent commits accepted work only when persistence is required or requested.
12. Main agent promotes the next accepted slice or checks in with the user.

No product code may be touched before steps 1-7 are complete.

## Research Cache

Research cache is evidence, not sprint planning.

It must include:

- Sources read in order.
- Exact files and line numbers.
- Current-code facts, reference facts, ABI facts, and test facts.
- Owner roles and proposed shape.
- Required assertions and required tests.
- Risks, stop conditions, proof gaps, and readiness judgment.

Reject and reseed research if it is vague, not line-backed, missing required
sources, merges planning with evidence, or authorizes coding.

## Scratchpad

Scratchpad defines the sprint into actionable pieces of work.

It must include:

- Accepted research cache path.
- Decisions and non-goals.
- Worker-ready slices with exact files, symbols, owners, invariants, tests, grep
  gates, and stop conditions.
- Follow-up slices and proof gaps.
- Completion criteria and signoff space.

Reject the scratchpad if any slice requires worker invention, allows broad file
sets, lacks exact tests, lacks stop conditions, conflicts with the research
cache, or preserves stale structure for convenience.

## Current Slice

`current.txt` contains exactly one active slice.

It must include:

- Scratchpad and research cache paths.
- Allowed files.
- Required shape.
- Non-goals.
- Stop conditions.
- Verification commands.

Reject or rewrite `current.txt` before worker seeding if it is stale, broad,
contains multiple slices, lacks exact allowed files, or leaves naming/ownership
choices to the worker.

## Hard Stops

Restart at the earliest broken stage if any of these happen:

- Research cache is missing, weak, stale, or not source-backed.
- Scratchpad is missing, weak, stale, or not derived from accepted research.
- `current.txt` is stale, broad, ambiguous, or not reviewer-accepted.
- Worker needs to invent owner names, paths, tests, ABI consequences, or scope.
- Public ABI changes appear without an explicit ABI-product slice.
- Host/runtime behavior changes appear in a cleanup-only slice.
- Tests are moved, deleted, filtered, or weakened without explicit proof.
- A compatibility shim, umbrella runtime, manager, engine, controller, `utils`, or
  fake alias appears without explicit authorization.
- Main agent starts product coding without explicit user override.
- Reviewer rejects research, scratchpad, or worker diff.

## Verification And Commit

- Verification commands must come from `current.txt`.
- Run the narrow package gates before root gates when applicable.
- Record failed or skipped verification honestly.
- Commit only after reviewer acceptance and required verification.
- Before committing, inspect status, diff, and recent log; stage only intended
  files.
- Do not amend, force-push, or use destructive git commands unless explicitly
  requested.

## Operating Rules

- Slow source-backed progress beats fast fake progress. Slow does not mean the
  smallest possible diff or one tiny paper-over slice at a time. Slow means doing
  the foundation correctly, including broad changes when ownership, ABI shape, or
  source structure is wrong.
- Small slices do not require tiny diffs; they require exact ownership and enough
  scope to remove the actual wrong foundation.
- If the existing shape is wrong, reshape toward the smallest true owner.
- Preserve ABI boundaries. Hosts depend on Howl C ABIs, not Zig convenience
  imports.
- Keep main-thread/runtime policy centralized with the true owner.
- If the problem is intense, stop inventing and eat the elephant byte by byte.
