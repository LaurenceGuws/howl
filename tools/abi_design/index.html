Captain’s role

Understand consequential choices. Decide when behavior, ownership or scope is ambiguous. Routine choices arrive with explanations.

Review status

Local lifecycle, presentation, copied queries and retained requests are independently reviewed. Remote correctness and cross-cut build reviews are closed by an accepted follow-up. The qualified backbone preserves host runtime ownership and local isolation; Flutter/Web adoption remains later.

The destination

Give Howl modules authoritative foreign interfaces, then replace host-owned copies in stages. Odin keeps its application bindings and composes Instance, Render and Server-client capabilities as appropriate. Ordinary Zig consumers retain the direct Zig APIs.

Standalone foreign qualification and production adoption serve different purposes. Neither requires moving Odin’s runtime into Howl. The first small implementation does not define the limit of the final product.

No packaging overhaul, new transport/security, mobile runtime redesign, WL/VK work or terminal-engine rewrite is part of this scope. This page records conclusions and progress; raw review traces and disposable probes stay in the workstream.

Choices and reasons

Agreed = Captain-aligned direction. Proposed = mechanism awaiting concrete contract review. Observed = traced current source, not a new runtime qualification.

D01 · Agreed · Modules are products

Choice. Each module owns its Zig and foreign interfaces. Odin and Flutter must not remain accidental owners of Instance contracts.

Why. Earlier review treated ABI creation as a host-refactoring exercise. The goal is a reusable product interface, with staged adoption by maintained foreign hosts.

Evidence / next proof. Independent C/C++ use qualifies the contract; host deletion is a downstream migration result, not an entry requirement.

D02 · Agreed · Odin first

Choice. Review Odin’s existing FFI before copying or moving it. Its current shape is not Captain-vetted.

Why. Existing engineering is a behavioral reference, not authority over ownership.

Evidence / next proof. Produce an export/caller/owner map and explain each stay, move or split.

D03 · Agreed · Host keeps scheduling

Choice. Odin chooses its workers, waits, queues, wakes, visible panes and presentation pacing.

Why. Howl needs to expose capabilities and scheduling facts without defining an Odin application runtime.

Evidence / next proof. Show local and remote progress without coupling terminal execution to a backend.

D04 · Observed · Local presentation credit

Choice. After successful SDL.RenderPresent, Odin grants a coalesced credit through native_terminal_request_render. The terminal worker may prepare changed content.

Why. This limits optional local projection work; PTY/VT service continues without that credit. Remote rendering uses a separate mailbox.

Evidence / next proof. Source: hosts/howl-odin/main.odin, desktop_render_io.odin and native/bridge.zig. Stalled-presentation and wake/quiet-publication proofs rerun in the native bridge Safe qualification.

D05 · Agreed · Complete frames

Choice. Keep complete drawing-command frames with incremental resource uploads/removals.

Why. Render can reuse rows and retained content internally. Embedders need not reconstruct a scene from missed dirty patches. A complete command frame is not a full framebuffer copy.

Evidence / next proof. Source: mods/howl-render/src/renderer.zig and mods/howl-instance/src/publication.zig. Pixel equivalence and cost qualification belong to implementation.

D06 · Qualified · Bulk frame access

Choice. Acquire an immutable frame, bulk-copy Render-owned command records, borrow upload pixels, then release it with explicit feedback.

Why. Local pointers and counts can avoid per-command FFI calls and serialization. Layout, bounds and lifetime must be explicit.

Evidence / next proof. Foreign C proves feedback rejection/recovery, immutable pixels during producer progress, replacement uploads and checked teardown with endpoint pinning between leases.

D07 · Agreed · Separate local and remote

Choice. Local uses direct Instance/VT. Server uses headless Instances and VT-owned encoding; its client decodes observations for local Render.

Why. The local happy path must not import Server or serialize its own state.

Evidence / next proof. Preserve build isolation and qualify equivalent rendering from local and remote observations.

D08 · Qualified · First native artifact packaging

Choice. Use the exact local Instance specialization in an optional shared native library. Existing Zig builds do not call through C. Linux standalone lifecycle is the first runtime qualification target; Windows lifecycle is explicitly unsupported by this first cut.

Why. The pinned self-hosted compiler panics when a static archive carries shared system-library dependencies. A minimal reproduction confirms it. The same graph builds as a shared library without changing compiler or core composition. This is a distribution choice, not a new runtime.

Proof. Standalone C lifecycle and C++ header/link proof pass. Initial default root passed 271/271; distribution and affected ReleaseSafe proofs passed. The review found and prompted a correction to continuation-cell identity; corrected default root passed 271/271 with 775 reported tests; follow-up review cleared the blocker. Initial Safe ELF is 21,391,726 bytes including debug data, with about 4.12 MB of text/data/BSS and FreeType/Harfbuzz dependencies. This is not an idle-memory measurement. Odin keeps its retained-request policy; initial standalone service is explicitly headless.

D09 · Qualified · Frame lifetime and bulk access

Choice. The terminal worker opens a module-owned endpoint and supplies its first fresh frame. The endpoint pins publication storage between frames; a lease pins the frame being read. Checked destruction refuses a live endpoint or lease before stopping the child.

Why. SDL must finish reading before memory is freed. Replacement backends start with empty residency so old textures are never silently assumed. Opening/handoff is an Odin worker request, not a Howl scheduler.

Boundary cost. Zig drawing unions stay private. Render projects the complete command array directly into caller-owned native records in one call. Pixel uploads borrow immutable lease bytes, avoiding an extra Local pixel copy. Odin retains commands for its own redraw lifetime and retains its texture-cache policy.

Proof. A real foreign C peer holds a frame while the producer advances, rejects malformed feedback without losing its lease, verifies teardown remains busy between leases, and replaces the backend with required uploads. Default root passes 279/279 steps. Odin’s 210 tests and focused Safe frame/native bridge proofs pass. A private graphical run qualifies real local PTY input, combining/wide Unicode output, resize, tab return and graceful close. Review found an unrelated copy ceiling that could make a valid large frame impossible to consume. The copy now uses the actual leased count; a real 225×512 C proof crosses the old ceiling, and count bounds are checked before acquisition. Follow-up review accepted the fixes. The installed app was not changed.

D10 · Qualified · Copied VT queries

Choice. VT owns copied selection, exact within-row search, link, visual-row and interaction records plus projection. Instance’s C ABI forwards its const observation. Odin calls the same module helpers under its terminal-worker claim.

Why. Terminal coordinate and Unicode rules should have one owner. Odin retains request queues, Find UI, clipboard/browser actions and diagnostics. A query copies its result synchronously; it exposes no live mutable terminal pointer.

Failure contract. Selected text is complete or fails without partial byte writes. A short link buffer reports the required length. Selection and links require matching columns and screen bank; unrepresentable native row coordinates fail explicitly.

Proof. Root 279/279 and focused Safe checks pass. VT native has 12 tests; Odin has 211. Independent C queries exercise a real Instance. A private graphical canary finds the marker and navigates both directions through Odin’s worker. Review found an inherited tall-cell/soft-wrap word-selection cycle. Traversal now skips repeated lower-row occupancy and guarantees direction; unit and real C proofs cover the exact case and a space boundary. Follow-up review accepted the correction.

D11 · Qualified · Pending terminal requests

Choice. VT owns copied native request fields and exact-head payload access. Instance owns consume and named replies. Odin keeps deciding how to handle clipboard, attention, pointer and window requests.

Why. Local requests should not use Server metadata or packed reply bytes. Odin can read a small descriptor without copying an unused large packet; a consumer needing the body asks for a checked complete copy.

Concrete distinction. A pointer query requests a reply but canonical VT allows consumption. Its native field says query requested; reply required describes heads that cannot be consumed without a typed response. Odin retains its default pointer reply.

Proof. Default root 279/279; focused Safe proofs and Odin’s 213 tests pass. The C peer preserves a clipboard head through invalid/stale/short-buffer calls, then observes exact reply bytes. A private Odin child verifies empty clipboard, default pointer and exact 32×128 screen replies. Independent review accepted the request cut. The private canary also exercises the Odin raw union across the real shared-library boundary.

D12 · Qualified · Server-client owns remote native adaptation

Choice. Optional Server-client native module decodes its wire metadata into the same VT-owned request facts as Local. It adds explicit Server authority beside those facts and exposes named replies. Odin shares its platform request policy across both routes.

Why. The app should supply screen dimensions or clipboard bytes without encoding a Server packet. Neither native module nor C artifact supplies workers, reconnect policy or a runtime.

Failure and lifetime. Request views own immutable body bytes independently of connections. Opening and observing never claim authority; existing Server headless behavior applies until explicit acquisition. Complete Server rejection preserves a connection; malformed, incomplete or allocation-interrupted responses retire it.

Proof. Focused Safe hostile fixtures, real Server/PTY C consumer, Odin bridge Safe and frontend pass. Review caught contradictory clipboard facts, incorrect outbound reply ceilings and a shared-source build conflict. All are corrected and follow-up review accepts the cut. Full root passes 284/284; Server Safe has 186 tests, including 10 hostile/native cases and real C. Odin Safe has 23 bridge tests and 212 frontend tests; a private remote canary proves exact replies and detach preserves the Server Instance. C selection/search and raw/delta cache entry points are not added by this cut; existing owned Zig capabilities and host history paging remain.
